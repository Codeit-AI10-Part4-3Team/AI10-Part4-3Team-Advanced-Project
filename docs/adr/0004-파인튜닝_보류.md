# ADR-0004: 파인튜닝은 하지 않고, `training/`은 로컬 모델을 채택할 때까지 비워 둡니다

- **상태**: Accepted
- **날짜**: 2026-08-13
- **결정자**: 신호정 (TL). 근거는 2026-08-11 회의의 이미지 생성 경로 결정
- **관련**: [ADR-0003](0003-이미지_생성_경로.md), [ADR-0002](0002-학습_파이프라인_배치.md),
  [구현_범위.md](../공통_가이드/구현_범위.md) 3절,
  [미결정_대장.md](../기술문서/미결정_대장.md) A-5,
  [training/AGENTS.md](../../training/AGENTS.md)

## 배경

**하지 않기로 한 결정입니다.** 이런 결정은 아무도 문서로 쓰지 않아서 가장 자주 잊힙니다. 지금
저장소를 처음 여는 사람은 `training/` 디렉토리와 `training/configs/brand-lora.example.yaml`을
보고 파인튜닝이 진행 중이라고 읽게 됩니다.

실제 상태는 이렇습니다.

- **기획서에 파인튜닝이 없습니다.** 기획서 전체에서 "파인튜닝"과 "LoRA"의 언급 횟수는 0회입니다
  (2026-08-13 확인). 기획서 15절의 검증 8과제에도 학습은 없습니다.
- **[ADR-0003](0003-이미지_생성_경로.md)이 이미지 생성 경로를 외부 API로 정했습니다.** 외부 API로
  제공되는 이미지 모델의 가중치는 우리가 만질 수 없으므로, 파인튜닝은 **로컬 모델 채택에
  종속됩니다.** 로컬 모델 채택 여부는 검증 4순위 결과 대기 중입니다.
- **하드웨어가 학습을 전제로 배정된 것이 아닙니다.** GPU는 한 대뿐이고 가용 VRAM 22.5GB, 호스트
  RAM 16GB, 디스크 100GB입니다 ([ADR-0011](0011-배포_환경_스펙과_권한_경계.md)). 같은 GPU에서
  학습과 추론이 동시에 VRAM을 요구하면 둘 다 실패합니다.
- **남은 일정이 학습을 감당하지 않습니다.** 실작업 22일 중 9일이 지났고, 워킹 스켈레톤 관통의
  실질 마감이 2026-08-14입니다. 학습 데이터 확보와 권리 대장 작성이 선행되어야 하는데
  ([training/data/README.md](../../training/data/README.md)) 그 작업은 시작되지 않았습니다.

그런데 **저장소의 여러 문서가 파인튜닝을 프로젝트 정의로 서술하고 있었습니다** -- 루트
`AGENTS.md`, `README.md`, [개발자_가이드.md](../공통_가이드/개발자_가이드.md)가 그렇습니다. 근거
등급 문서가 기획서와 다른 이야기를 하면 정본이 둘이 됩니다. 이 ADR과 같은 PR에서 정정합니다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. **파인튜닝을 하지 않고, `training/`은 되살릴 조건과 함께 비워 둔다** | 남은 일정을 스켈레톤 관통과 검증에 씁니다. 되살릴 조건이 문서에 남아 나중에 판단할 수 있습니다 | "LoRA 파인튜닝"을 프로젝트 소개로 써 온 문서들을 함께 고쳐야 합니다 |
| B. 축소된 형태로라도 1회전을 돌린다 | 중간 점검의 원래 판정 기준("파인튜닝 1회전 완료")을 충족합니다. 학습 경험이 산출물에 남습니다 | 외부 API를 쓰는 이상 그 어댑터를 **서빙에 쓸 곳이 없습니다.** 데이터 권리 대장도 없이 학습하면 배포 판단을 내릴 수 없게 됩니다. 관통이 마감인 주에 GPU를 학습에 내줍니다 |
| C. `training/` 디렉토리를 삭제한다 | 오해가 원천적으로 사라집니다 | 로컬 모델을 채택하면 [ADR-0002](0002-학습_파이프라인_배치.md)의 배치 결정을 처음부터 다시 해야 합니다. 되살릴 조건이 남지 않습니다 |

## 결정

**A를 택합니다.** 이번 범위에서 파인튜닝(LoRA)과 어댑터 배포를 **하지 않습니다.**
`training/`은 삭제하지 않고 [ADR-0002](0002-학습_파이프라인_배치.md)의 배치 그대로 비워 둡니다.

B를 택하지 않은 이유는 **쓸 곳 없는 산출물을 만들기 때문**입니다. 학습된 어댑터는 로컬 모델에
얹히는 물건인데 생성 경로가 외부 API입니다. 중간 점검 기준을 맞추려고 돌리는 학습은 기준을
충족시키는 것이 아니라 기준이 실제와 어긋나 있다는 사실을 가립니다.

C를 택하지 않은 이유는 **되살릴 경로를 지우기 때문**입니다. 검증 4순위에서 로컬 모델이 채택되면
학습이 다시 안건이 되고, 그때 `training/`이 없으면 배치 결정부터 다시 합니다.

## 결과

**생기는 제약**

- **`training/`에 새 코드를 넣지 않습니다.** 지금 있는 것은 골격과 예시 config이며, 이 상태가
  의도된 상태입니다. 비어 있다고 채우지 마세요.
- **`training/`과 `apps/` 사이의 양방향 import 금지는 그대로 유효합니다.** 보류는 경계를 푸는 것이
  아닙니다. 나중에 되살릴 때 그 경계가 없으면 [ADR-0002](0002-학습_파이프라인_배치.md)가
  무의미해집니다.
- **파인튜닝을 프로젝트 소개로 쓰지 않습니다.** 발표 자료와 제출 문서에서도 같습니다. 하지 않은
  것을 했다고 적는 것은 산출물의 신뢰를 통째로 잃는 방식입니다.
- **브랜드 스타일 일관성은 프롬프트 설계로 답합니다.** 파인튜닝이 맡을 예정이던 자리이며,
  검증 3순위(캐릭터와 화풍 일관성)가 그 답의 근거가 됩니다.

**쉬워지는 것**

- GPU 시간 분할 규칙 합의가 스켈레톤 기간에는 불필요해집니다 (리스크 1번). 학습이 없으면
  VM의 GPU는 검증 실험만 씁니다.
- 학습 데이터 권리 대장이 배포 전 차단 항목에서 빠집니다. 다만 **삭제하지 않습니다** --
  되살릴 때 다시 필요합니다.

**어려워지는 것**

- **과제 요구사항과의 대응을 따로 설명해야 할 수 있습니다.** "브랜드 데이터로 파인튜닝"을
  기대하는 독자에게는 결과물이 다르게 보입니다. 그 설명의 근거가 이 ADR입니다.

**다루지 않는 것**

- **중간 점검(08-17)의 판정 기준은 이 ADR이 정하지 않습니다.** 원래 기준이
  "파인튜닝 1회전 완료 + VM GPU 추론 관통"이라 이 결정으로 충족될 수 없게 되지만, 기준 변경은
  PM 소관이고 확정 근거는 회의록입니다. TL 초안과 대기 상태는
  [00-overall.md](../역할_일정/00-overall.md) 3-b절에 있습니다.
- 로컬 모델을 채택했을 때의 어댑터 설계는 별도 ADR입니다 (2026-08-11 회의 결정, 소관 임유빈 + 신호정).

**재검토 신호**

- **검증 4순위에서 로컬 모델을 채택할 때.** 이것이 이 결정을 되살리는 유일한 신호입니다.
  그 시점에 필요한 것은 학습 데이터 권리 대장, GPU 시간 분할 규칙, 그리고 어댑터 ADR입니다.
- 브랜드 데이터셋의 출처와 권리 범위가 확정되고, 프롬프트만으로 브랜드 톤이 고정되지 않는다는
  실측이 나올 때.
