# 기술문서

기획서를 **구현할 수 있는 형태로** 옮긴 문서군입니다. 기획서 14.2 단계 2의 산출물이며, 완료
조건은 "스키마, API, 모듈 구조 확정"입니다.

## 기획서와의 경계

| | 기획서 | 기술문서 |
|---|---|---|
| 답하는 질문 | 무엇을, 왜 | 어떻게 |
| 정본 | [docs/기획서/기획서.md](../기획서/기획서.md) | 이 폴더 |
| 바뀌는 계기 | 팀 합의 | 기획서 변경 또는 실험 결과 |
| 소관 | PM (정승호) | TL (신호정) |

**뜻이 바뀌면 기획서를 먼저 고칩니다.** 기술문서가 기획서와 다른 말을 하기 시작하면, 팀은 둘 중
어느 쪽을 읽어야 하는지 알 수 없게 되고 결국 둘 다 읽지 않습니다.

구조 규칙(의존 방향, 경계, CI 계약)은 여기가 아니라 [AGENTS.md](../../AGENTS.md)와
[docs/공통_가이드/](../공통_가이드/)가 정본입니다. 이 폴더는 **도메인**을 다룹니다.

## 지금 상태

이 문서군은 **초안**입니다. 기획서 18절의 항목이 열려 있는 상태에서 작성되었기 때문에, 그 항목에
걸리는 결정은 "TL 잠정안"으로 적혀 있습니다.

**2026-08-11 회의로 차단 항목이 7건에서 4건으로 줄었습니다**
([미결정_대장.md](미결정_대장.md) 상단 요약). 남은 차단은 A절 2, 3, 6번과 B절 20번이며, 셋은
검증 실험 결과를 기다리고 하나는 일정 확정을 기다립니다.

- 잠정안은 **반박당하기 위한 것**입니다. 회의에서 아무도 반박하지 않으면 그대로 확정됩니다.
- 무엇이 잠정인지는 [미결정_대장.md](미결정_대장.md) 한 곳에서 확인할 수 있습니다. 각 문서의
  마지막 절에도 같은 목록이 있습니다.
- **잠정 표시가 없는 서술은 기획서에서 직접 도출된 것**이며, 바꾸려면 기획서를 고쳐야 합니다.

2026-08-09에 **기술문서를 쓰면서 생긴 미결정 15건 중 13건이 확정되었습니다**
([미결정_대장.md](미결정_대장.md) C절). 스키마와 계약을 고정하는 데 필요한 답은 전부 나온
상태이고, 남은 미결정은 기획서 18절 유래 항목(타 소관)과 실험 결과 종속 항목뿐입니다.

확정된 결정 중 근거 문서를 고친 것 둘은 ADR로 남아 있습니다:
[ADR-0005](../adr/0005-열화_폴백은_자동화_생략으로_한정.md)(열화 폴백 범위),
[ADR-0010](../adr/0010-상태_저장소와_파일_보관_위치.md)(상태 저장소).

리뷰에서 새로 생긴 결정도 ADR로 남깁니다:
[ADR-0012](../adr/0012-시안_생성_실패_시_브리프_잠금_해제.md)(시안 생성 실패 시 브리프 잠금 해제).
**결정이 문서 본문에만 있으면 다음 사람이 그것을 결정으로 읽지 않습니다.**

## 개정 절차

기획서 14.3의 문서 관리 원칙을 그대로 따릅니다.

1. 회의를 하면 회의록을 남기고, 그 회의록을 근거로 이 문서군을 고칩니다. 기술문서 안에서 생긴
   미결정(대장 C절)은 예외로 TL이 확정하며, 근거는 해당 문서 또는 ADR입니다
   ([미결정_대장.md](미결정_대장.md) "누가 확정하는가").
2. 반영은 TL이 합니다.
3. 확정된 항목은 [미결정_대장.md](미결정_대장.md)의 열린 표에서 빼고, 해당 문서의 잠정 표시도
   함께 지웁니다. 한쪽만 고치면 대장과 본문이 다른 말을 합니다.
4. 아키텍처를 바꾸는 결정은 [docs/adr/](../adr/)에 ADR로 남깁니다.
5. Git에 올라가지 않은 것은 공유되지 않은 것입니다. 구두 합의는 결정이 아닙니다.

## 작성 규약

문체와 문자 규칙의 정본은 [문서_작성_규약.md](../공통_가이드/문서_작성_규약.md)입니다.
이 문서군은 그 규약의 적용 대상이며, 요약하면:

- 문서는 한글, 코드와 계약과 경로는 영어입니다 ([AGENTS.md](../../AGENTS.md) 명명 규약).
- 경어체를 씁니다. 읽는 대상에 심사자가 포함됩니다.
- 키보드로 입력할 수 없는 문자를 쓰지 않습니다. 가운뎃점, em dash, 화살표 기호는 쉼표와 하이픈과
  `->`로 바꿉니다. 백틱 안의 코드와 경로는 예외입니다.
- 다이어그램은 mermaid로 씁니다. 이미지는 diff에 변경이 보이지 않습니다.
- **규칙에는 이유를 함께 적습니다.** 이유 없는 규칙은 사람도 에이전트도 무시합니다.

제출 전에는 규약 5절의 점검 스크립트를 원본 마크다운에 돌립니다. PDF로 변환한 뒤에는 이미
치환되거나 사라진 문자를 찾을 수 없습니다.
