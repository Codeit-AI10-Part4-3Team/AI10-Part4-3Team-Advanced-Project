# ADR-0013: 로그인 토큰은 서명한 무상태 토큰으로 발급하고, 서버는 폐기하지 않는다

- **상태**: Proposed
- **날짜**: 2026-08-12
- **결정자**: 임동규 (05 백엔드/인프라). 합의 대기: 신호정 (02 TL), 정승호 (01 PM)
- **관련**: [ADR-0008](0008-로그인_수단과_스켈레톤_범위.md),
  [ADR-0010](0010-상태_저장소와_파일_보관_위치.md),
  [세션_보관_정책.md](../기술문서/세션_보관_정책.md) 1.4절,
  [API_계약.md](../기술문서/API_계약.md) 6절,
  [openapi.yaml](../../packages/contracts/openapi.yaml)의 `securitySchemes`

## 배경

로그인에 관해 이미 정해진 것이 셋 있습니다.

| 정해진 것 | 어디에서 |
|---|---|
| 수단은 아이디와 비밀번호 | [ADR-0008](0008-로그인_수단과_스켈레톤_범위.md) |
| 수명은 24시간 고정, 갱신 경로 없음 | [세션_보관_정책.md](../기술문서/세션_보관_정책.md) 1.4절 |
| 전달은 `HttpOnly` 쿠키 `session_token` | [API_계약.md](../기술문서/API_계약.md) 6절, `openapi.yaml` |

정해지지 않은 것이 하나 남았습니다. **토큰 안에 무엇이 들어가고, 서버가 그것을 폐기할 수
있는가**입니다. S0(로그인)은 이 답 없이는 첫 줄도 쓸 수 없어 여기서 정합니다.

이 결정을 둘러싼 제약은 아래와 같습니다.

- **워커 프로세스는 1개**입니다 ([ADR-0011](0011-배포_환경_스펙과_권한_경계.md)). 인증 검사는
  모든 요청에 걸리므로, 여기에 블로킹 I/O가 들어가면 그 비용을 전 요청이 나눠 냅니다
  ([API_계약.md](../기술문서/API_계약.md) 2.2절).
- **상태 저장소는 SQLite 파일**입니다 ([ADR-0010](0010-상태_저장소와_파일_보관_위치.md)).
  SQLite 접근은 블로킹 I/O입니다.
- **S0의 완료 목표는 08-13이고 S2(세션 상태 저장소)는 08-14**입니다
  ([역할_일정/05-백엔드_인프라.md](../역할_일정/05-백엔드_인프라.md)). S0이 저장소를 요구하면
  앞 항목이 뒤 항목을 기다립니다.
- **계약이 정의한 로그아웃은 204와 쿠키 만료뿐**입니다. 서버가 토큰을 죽이라는 요구가 계약
  어디에도 없습니다.
- **저장소가 public이고 사용자는 팀 내부입니다** (기획서 11.2). 계정은 고정 둘입니다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 서명한 무상태 토큰** (`userId` + 만료 시각에 서버 비밀키로 서명) | 검증에 I/O가 없음. 저장소에 의존하지 않아 S0을 S2보다 먼저 닫을 수 있음. 재시작을 견딤 | 발급한 토큰을 서버가 되돌릴 수 없음. 서명 키가 새면 전 계정 위조 |
| B. SQLite에 저장하는 불투명 토큰 | 즉시 폐기 가능. 로그인한 기기 목록을 만들 수 있음 | 모든 인증 요청에 SQLite 읽기가 붙음(워커 1개). S0이 S2에 의존. 만료 토큰 정리 배치가 하나 더 생김 |
| C. 프로세스 메모리에 두는 토큰 표 | 구현이 가장 작고 폐기도 가능 | 재시작하면 전원이 로그아웃됩니다. 배포할 때마다 일어납니다 |

## 결정

**A를 택합니다.** 토큰은 `userId`와 만료 시각을 담아 서버 비밀키로 서명한 문자열이며, 서버는
발급한 토큰을 폐기하지 않습니다. 로그아웃은 쿠키를 지우는 것으로 끝납니다.

B를 택하지 않은 이유는 **B가 주는 값을 계약이 요구하지 않기 때문**입니다. B의 실익은 즉시
폐기인데, 계약의 로그아웃은 쿠키 만료이고 비밀번호 변경과 탈퇴는 둘 다 501입니다
([ADR-0008](0008-로그인_수단과_스켈레톤_범위.md)). 즉 **지금 이 시스템에는 토큰을 죽여야 하는
사건 자체가 없습니다.** 그 대가로 치르는 것은 모든 요청에 붙는 SQLite 읽기와, S0이 S2를
기다리게 되는 일정 결합입니다. 값을 하지 않는 기능에 두 비용을 내지 않습니다.

C를 택하지 않은 이유는 [ADR-0010](0010-상태_저장소와_파일_보관_위치.md)이 인메모리를 배제한
것과 같습니다. **유실이 사용자에게 보이고, 재시작은 배포할 때마다 일어납니다.**

토큰을 표준 JWT로 만들지 자체 서명 문자열로 만들지는 **이 결정의 범위가 아닙니다.** 둘 다 A의
구현이며, 라이브러리 선택은 PR에서 근거와 함께 정합니다.

## 결과

### 생기는 제약

- **로그아웃해도 이미 새어 나간 토큰은 남은 수명 동안 유효합니다.** 이것은 결함이 아니라 이
  결정의 값입니다. "로그아웃했는데 토큰이 살아 있다"를 버그로 보고 폐기 목록을 넣으려는 변경은
  **이 ADR을 먼저 열어야 합니다.** 코드만 읽어서는 이 성질이 의도된 것인지 알 수 없기 때문에
  여기 적습니다.
- **서명 키가 새면 전 계정을 위조할 수 있습니다.** 비밀번호 해시보다 파급이 큽니다. 키는
  `infra/.env`에만 두고 `.env.example`에는 이름만 남깁니다. 이 저장소는 public이라 예외가
  없습니다.
- **서명 키에 기본값을 두지 않습니다.** 기본값을 두면 그 값이 곧 저장소에 공개된 서명 키가
  되고, 배포에서 그대로 쓰여도 아무도 눈치채지 못합니다.

  **기동 실패의 조건은 "계정이 저장소에 있는데 키가 없을 때"입니다**
  (2026-08-13 구현 시 확정, 2026-08-14 정정). 키가 비었다는 이유만으로 무조건 실패시키면
  `.env` 없는 새 클론이 뜨지 않는데, 그것은 워킹 스켈레톤이 지켜야 하는 성질과 충돌합니다.
  계정이 있다는 것은 여기서 인증을 쓸 생각이라는 뜻이고, 배포에는 항상 고정 계정이
  있으므로([ADR-0008](0008-로그인_수단과_스켈레톤_범위.md)) **배포는 언제나 즉시
  실패합니다.** 두 규칙이 함께 성립하는 지점이 여기입니다.

  주의: **조건은 `ADGEN_ACCOUNTS` 가 아니라 저장소를 봅니다.** 처음에는 환경변수를 보게
  구현했는데, 그러면 이름 있는 볼륨([ADR-0014](0014-상태_파일은_이름_있는_볼륨에_둔다.md))
  위에서 둘이 갈라집니다. `.env` 없이 재기동하면 시드는 아무것도 지우지 않아 계정은 그대로
  남는데 검사는 건너뛰고, 올바른 비밀번호로 로그인하면 발급 단계에서 500 이 났습니다
  (2026-08-14, PR #84 리뷰에서 신호정 발견). 환경변수는 "이번 기동에 무엇을 시드하라고
  했는가"이고 저장소는 "실제로 무엇이 있는가"이며, 인증이 동작해야 하는지를 정하는 것은
  뒤쪽입니다.

  키가 없는 채로 뜬 서버에 쿠키가 실려 오면 검증은 **예외가 아니라 401** 입니다. 키가 없으면
  어떤 토큰도 유효할 수 없으므로 그것은 오류가 아니라 실패한 검증이고, 예외로 두면 500 이
  나갑니다(2026-08-13 실측). 발급은 반대로 예외입니다 - 아무도 믿을 수 없는 토큰을 만드느니
  만들지 않는 편이 낫습니다. 어느 경우에도 **빈 키로 실제 검증을 수행하지는 않습니다.**
  그렇게 하면 공격자가 같은 빈 키로 서명한 토큰이 통과합니다.
- **토큰에 개인정보를 넣지 않습니다.** `userId`와 만료 시각만 담습니다. 서명은 위조를 막을 뿐
  내용을 가리지 않으므로, 쿠키를 열어 보는 사람에게 그대로 읽힙니다.
- **만료 판정이 서버 시계에 의존합니다.** 시계가 크게 틀어지면 멀쩡한 토큰이 거부되거나 만료된
  토큰이 통과합니다.
- **비밀번호 변경, 탈퇴, 강제 로그아웃 중 하나라도 구현하기로 하면 이 결정이 곧바로 걸립니다.**
  지금 성립하는 이유가 "그 경로가 없어서"이기 때문입니다.

### 쉬워지는 것

- **토큰 검증이 저장소를 요구하지 않습니다.** 따라서 S2(세션 상태 전이)의 테이블이 완성되기
  전에도 인증 경로를 닫을 수 있습니다.
  주의: **계정 자체는 저장소에 둡니다.** [ADR-0010](0010-상태_저장소와_파일_보관_위치.md)이
  계정을 SQLite 파일에 두기로 정했고, 고정 계정 둘은 기동 시 `infra/.env`의 값으로 시드합니다
  ([ADR-0008](0008-로그인_수단과_스켈레톤_범위.md)). 이 결정이 없애는 것은 **토큰을 위한
  저장소**이지 계정을 위한 저장소가 아닙니다.
- 인증 검사에 I/O가 없어, 워커 1개에서 모든 요청이 무는 고정 비용이 줄어듭니다.
- 워커를 늘리게 되어도 이 결정은 그대로 성립합니다. 공유할 상태가 없습니다.

### 어려워지는 것

- 강제 로그아웃, 로그인한 기기 목록, 토큰 재사용 탐지는 전부 불가능합니다. 필요해지면 B로
  옮기는 이관이 따릅니다.

### 재검토 신호

- 외부 공개로 사용자가 팀 밖으로 나갈 때 (기획서 17.2). OAuth 전환과 함께 다시 엽니다.
- 비밀번호 변경 또는 탈퇴가 501을 벗어날 때 ([ADR-0008](0008-로그인_수단과_스켈레톤_범위.md)).
- 서명 키가 유출되어 회전이 필요해질 때. 무상태 토큰은 키를 바꾸는 순간 전원이 로그아웃됩니다.
- 즉시 강제 로그아웃 요구가 실제로 생길 때. 추측으로 옮기지 않습니다.
