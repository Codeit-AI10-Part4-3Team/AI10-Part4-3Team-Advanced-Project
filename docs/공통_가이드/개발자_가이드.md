# 프로젝트 참여자 가이드

팀원·협업자가 프로젝트 배경과 작업 방식을 빠르게 파악하기 위한 문서입니다.
**아키텍처 규칙과 함정 목록은 [AGENTS.md](../../AGENTS.md)가 원천**이며, 이 문서는 사람이 읽는
입구 역할을 합니다.

## 1. 프로젝트 개요

- **무엇을 만드는가**: 글(제품·브랜드 정보)과 이미지(레퍼런스·제품컷)를 입력하면 **브랜드 스타일의
  광고 소재(이미지 + 카피)를 생성**하는 서비스입니다. 이미지 생성은 외부 API로 하며
  ([ADR-0003](../adr/0003-이미지_생성_경로.md)), GCP VM에 배포해 실제 사용자가 쓸 수 있는
  상태로 운영하는 것까지가 범위입니다. **파인튜닝(LoRA)으로 톤을 고정하는 경로는 이번 범위가
  아닙니다** ([ADR-0004](../adr/0004-파인튜닝_보류.md)). 브랜드 톤은 프롬프트 설계로 맞추고,
  로컬 모델을 채택하면 그때 다시 판단합니다.
- **누구의 어떤 문제를 푸는가**: 디자이너를 상시 두기 어려운 소상공인·소규모 마케팅 팀은 광고
  소재 한 벌에 외주 비용과 며칠의 리드타임을 씁니다. 범용 생성 도구를 쓰면 결과가 매번 다른 톤으로
  나와 브랜드 일관성이 무너집니다. **일관된 브랜드 톤을 유지한 채 분 단위로 소재를 뽑는 것**이
  우리가 푸는 문제입니다.
- **핵심 마일스톤** (2026): 착수 `08-04` · 계약 동결 `08-08` · 중간 점검 `08-17` ·
  배포 `08-24` · 제출 `08-31`. 실작업 **22일**입니다
  (일요일 4일 + 광복절 8/15(토) + 대체공휴일 8/17(월) 제외). 상세: [역할_일정/00-overall.md](../역할_일정/00-overall.md)
- **세부 범위는 아직 확정 전입니다.** 무엇이 미정인지는 [AGENTS.md](../../AGENTS.md)의
  "아직 확정되지 않은 것(TBD)" 절과 [구현_범위.md](구현_범위.md)를 보세요.

현재 코드에 있는 것은 **워킹 스켈레톤**입니다. 요청 하나가
`요청 → 도메인 처리 → 근거 검색 → 가드레일 생성 → 응답` 전 구간을 관통하지만, 외부 의존은
전부 오프라인 스텁이고 **도메인도 아직 광고 생성이 아닙니다**(템플릿이 갖고 온 질의응답).
이 스켈레톤의 값어치는 기능이 아니라 "폴백·가드레일·계약·CI가 실제로 동작한다"는 증명이며,
**각자 자기 이음매를 광고 생성으로 갈아끼우는 것**이 첫 스프린트의 일입니다.

## 2. 30분 안에 돌려보기

```bash
bash scripts/setup-dev.sh          # Windows: powershell -File scripts\setup-dev.ps1
python3 -m venv .venv && source .venv/bin/activate
pip install -e "./apps/backend[dev]" -e "./apps/ai-engine[dev]"
pip install pre-commit && pre-commit install && pre-commit install --hook-type pre-push

uvicorn ai_engine.service:app --reload --port 8100 &   # → :8100/docs
uvicorn api.main:app --reload --port 8000              # → :8000/docs

curl -X POST localhost:8000/v1/ask -H 'content-type: application/json' \
     -d '{"question":"환불은 어떻게 하나요?"}'
```

ai-engine을 끄고 같은 요청을 보내면 **200에 `messageMode: official_fallback`** 이 돌아옵니다.
그 열화는 버그가 아니라 설계된 동작입니다. 단, **`official_fallback`은 계약에서 이미 폐기된
값입니다** — 광고 도메인에는 대응하는 동작이 없어 `messageMode`는 `normal` / `degraded` 둘만
남습니다([용어_사전.md](../기술문서/용어_사전.md) 6절, [ADR-0005](../adr/0005-열화_폴백은_자동화_생략으로_한정.md)).
위 값은 아직 갈아끼우지 않은 스켈레톤 코드의 실제 출력이고, 이음매를 교체하는 PR에서 코드와 이
문서가 함께 바뀝니다.

> ⚠️ **파이썬 환경은 이 저장소 전용이어야 합니다.** 같은 템플릿에서 파생된 다른 레포가
> `api` · `backend_core` · `ai_engine`이라는 **똑같은 최상위 모듈명**을 씁니다. 한 인터프리터에
> 둘을 editable로 설치하면 이 저장소의 테스트가 **남의 소스를 import한 채** 돌고, 증상이
> `ImportError` · `ValidationError`로 나타나 코드 결함으로 오진하기 쉽습니다(실측 사고 있음).
> 진단만 하려면 `bash scripts/setup-dev.sh --check` — E04가 이 경우를 잡습니다
> ([환경_세팅_가이드.md#e04](환경_세팅_가이드.md#e04)).

품질 게이트는 CI와 같은 것을 로컬에서 돌립니다:

```bash
bash scripts/run-tests.sh          # ruff + mypy + pytest + pre-commit 훅 전량 (= CI)
bash scripts/run-tests.sh --tests  # pytest만 (pre-push 훅이 쓰는 모드)
```

`ruff` · `mypy` · `pytest` 단계는 **`apps/` 두 곳만** 봅니다. `scripts/` · `e2e/`(지금) 와
`training/` · `packages/`(생기는 대로) 의 파이썬, 문서 위생(개행·줄 끝 공백), ruff 버전 동기화는
**pre-commit 단계에서만** 걸리므로, 그 단계를 건너뛰면 로컬은 초록인데 CI의
`Pre-commit hooks`(required)가 떨어집니다.

로컬에서 재현되지 않는 CI 검사는 **gitleaks 전체 트리 스캔** 하나입니다. 훅의 gitleaks는 staged
변경만 보도록 고정돼 있어 `--all-files`로는 아무것도 검사하지 않고, 대신 `ci.yml`이 별도 스텝으로
트리 전체를 훑습니다. 둘은 한 쌍이므로 어느 한쪽만 지우면 방어선이 사라집니다.

## 3. 반드시 지켜야 할 설계 원칙

전체 목록과 근거는 [AGENTS.md](../../AGENTS.md)의 "설계 제약" 절이 원천입니다. 요약하면:

- **근거 기반 생성**: 카피는 입력된 제품 정보에만 근거합니다. 이것은 취향이 아니라 법적 제약입니다 —
  없는 효능·수치를 지어내면 표시광고법상 허위·과장 광고가 됩니다.
- **열화는 자동화 생략 하나뿐입니다**: `brief:fill`이 죽으면 자동 채움을 건너뛰고 사용자 입력으로
  진행하며 그 사실을 `messageMode: degraded`로 드러냅니다. 시안 생성과 렌더에는 폴백이 없고 명시적
  오류입니다 — 카피는 제품마다 달라 사전 승인 응답이 성립하지 않기 때문입니다
  ([ADR-0005](../adr/0005-열화_폴백은_자동화_생략으로_한정.md)). 조용히 실패하는 것도, 모델 없이
  카피를 조립하는 것도 둘 다 금지입니다.
- **학습과 서빙은 파일로만 만납니다**: `training/`과 `apps/`는 서로를 import하지 않습니다.
- **GPU는 한 대**: 학습과 추론이 동시에 VRAM을 요구하면 둘 다 죽습니다. 시간을 나누거나 예산을
  명시적으로 분할하세요.
- **이미지 생성은 동기 HTTP로 처리하지 않습니다**: 잡 접수 → 조회 형태이며, 이 결정은 구현이 아니라
  계약(`packages/contracts/openapi.yaml`)에 먼저 들어갑니다.

## 4. 품질 검증 지표 (사람 채점이 아니라 코드로 재현 가능해야 함)

평가 자산은 [`apps/ai-engine/eval/`](../../apps/ai-engine/eval/)에 있고, 지표 함수는 순수 함수입니다.

| 지표 | 정의 | 목표(가설) |
|---|---|---|
| 생성 지연 | 잡 접수 → 결과 이미지 완료 (p50 / p95) | TBD |
| 브랜드 스타일 일치도 | 브랜드 레퍼런스셋 ↔ 생성물 스타일 임베딩 유사도 | TBD |
| 카피 사실 일치율 | 카피의 주장 중 입력 제품 정보로 뒷받침되는 비율 | TBD |
| 환각 억제율 | 가드레일 on/off 대조군의 사실 일치율 차이 | TBD |
| 열화 발생률 | 브리프 자동 채움을 건너뛴 세션 비율 (`messageMode: degraded`) | TBD |

- **채점 모델 ≠ 생성 모델** (자기채점 편향 배제)
- **스타일 일치도는 자동 지표만으로 판정하지 않습니다.** 임베딩 유사도는 색감에 반응할 뿐
  브랜드 정체성을 보지 않습니다. 블라인드 A/B 사람 평가를 함께 남기고, 자동 지표는 그것과의
  상관이 확인된 뒤 대리 지표로 씁니다.
- **목표치(TBD)는 첫 실측 이후에 채웁니다.** 실측 전에 적은 숫자는 근거가 아니라 희망입니다.
- 번들 더미 코퍼스로 측정한 숫자는 아무것도 증명하지 않습니다.
- **"폴백 발생률"이라는 지표는 없습니다.** 이 프로젝트에 남은 열화는 `brief:fill` 자동 채움 생략
  하나뿐이고, 시안 생성·부분 교체·렌더는 명시적으로 실패합니다
  ([ADR-0005](../adr/0005-열화_폴백은_자동화_생략으로_한정.md)).

`training/`은 상시 기동 배포 단위가 아니므로 **`apps/` 밖**에 있습니다
([ADR-0002](../adr/0002-학습_파이프라인_배치.md)).

## 7. CI 구성

워크플로는 **required(필터 없음) / non-required(paths 필터)** 두 갈래입니다. required check에
paths 필터를 걸면 해당 경로를 건드리지 않은 PR에서 체크가 생성되지 않아 머지가 영구 블록됩니다.

| 워크플로 | 잡 | required | 트리거 |
|---|---|---|---|
| `ci.yml` | `Pre-commit hooks`(훅 전량 + gitleaks 전체 트리) · `Lint & Type Check (backend/ai-engine)` · `Unit tests (backend/ai-engine)` | ✅ 5종 | 모든 PR |
| `frontend-ci.yml` | 프론트 lint/typecheck/build | ❌ | `apps/frontend/**` |
| `docker-build.yml` | 이미지 빌드 + `/health` 스모크, compose config 검증 | ❌ | `apps/*/Dockerfile`·`src/**`·`infra/**` |
| `contracts-check.yml` | OpenAPI 스펙 검증 | ❌ | `packages/contracts/**` |
| `e2e.yml` | 종단 관통 테스트 | ❌ | `e2e/**`·`apps/**`·`infra/**` |
| `notebook-check.yml` | 노트북 출력 셀 제거 확인 | ❌ | `**.ipynb` |
| `reviewdog.yml` | 린터 결과를 PR 변경 줄에 인라인 코멘트 | ❌ | 모든 PR (fork 제외) |
| `sonarqube.yml` | 정적 분석 + 커버리지 추세 | ❌ | 모든 PR + `main` push (fork 제외) |
| `ai-review.yml` | LLM 맥락 리뷰 (논리·경계·계약) | ❌ | 모든 PR (fork·draft 제외) |

required 5종의 **이름**은 `scripts/setup-github.sh`의 `contexts` 배열과 문자열이 정확히 일치해야
합니다: `Pre-commit hooks` · `Lint & Type Check (backend)` · `Lint & Type Check (ai-engine)` ·
`Unit tests (backend)` · `Unit tests (ai-engine)`. 매트릭스를 늘리거나 잡을 개명할 때는
두 곳을 **같은 PR에서** 고치세요 — 어긋나면 체크가 생성되지 않아 모든 PR이 영구히 "Expected"로
대기합니다.

`frontend-ci` · `docker-build` · `contracts-check` · `e2e` 네 종은 **대상 파일이 없으면 전 단계를
건너뛰도록** 작성돼 있어, 프론트엔드·Dockerfile·compose·스펙이 생기는 순간 별도 설정 없이
활성화됩니다. 그래서 지금 초록인 것이 "검사에 통과했다"는 뜻이 아닐 수 있습니다.

### 7-1. 보조 리뷰어 3종은 게이트가 아닙니다

`reviewdog` · `sonarqube` · `ai-review`는 조언을 붙이는 계층이고, 하드 게이트는 `ci.yml`입니다.
required로 올리지 않는 이유는 셋 다 **체크가 생성되지 않는 조건**을 갖고 있기 때문입니다 —
fork PR(시크릿 미주입), 키 미등록(`SONAR_TOKEN` · `ANTHROPIC_API_KEY`), draft PR. required로
지정하는 순간 그 조건에 걸린 모든 PR이 머지 불가가 됩니다. AI 리뷰는 크레딧이 소진되면 빨간 X
대신 **경고로 열화**합니다. 설정·비용 실측: [저장소_운영.md](저장소_운영.md) 8절.

### 7-2. 버전 핀은 두 종류입니다 (드리프트 실제 사고 있음)

| 대상 | 핀 위치 | 상향 방법 |
|---|---|---|
| **ruff** | 네 곳 — `.pre-commit-config.yaml` rev · `apps/backend`·`apps/ai-engine`의 dev extra `ruff==` · `reviewdog.yml`의 `RUFF_VERSION` | 네 파일을 **같은 PR**에서. `scripts/check_ruff_sync.py`가 `ruff-sync` 훅으로 강제 |
| **gitleaks** | 한 곳 — `.pre-commit-config.yaml` rev | rev만 올리면 됩니다. `ci.yml`의 전체 스캔 스텝이 그 값을 읽어 씁니다 |

ruff만 핀이 넷인 이유는 pip가 설치 시점에 버전을 고정해야 해 `pyproject.toml`에 문자열로 박히기
때문입니다. 한쪽만 올라가면 **같은 코드가 한쪽에서만 통과**합니다(Dependabot이 실제로 만든 적
있음 — [저장소_운영.md](저장소_운영.md) 4-1절). 버전 상향 PR을 받으면 네 곳을 먼저 확인하세요.
