제품, 장면, 대사, 인물은 하나로 고정했습니다. 8장 사이에서 달라지는 것이 화풍뿐이어야

## 넘길 것

채택된 조건의 이미지 8장과 그 조건의 `art_style_id` 를 넘깁니다.
**05 가 `ADGEN_ART_STYLES` 에 넣는 값이 이 문자열과 한 글자라도 다르면 예시와 실제 결과가
다른 문장에서 나옵니다.** 계약상 이 값은 `ArtStyle.artStyleId` 이고 그대로
`brief.artStyle` 에 실립니다.

**값과 서빙 경로가 2026-08-22 에 확정됐습니다** (PR #194 코멘트, 05 임동규). `artStyleId` 는
판정 제안 그대로이고, 서빙은 **backend 정적 마운트**입니다. 파일은 VM `adgen-state` 볼륨의
`/data/art-styles/` 에 두고 URL 은 `/static/art-styles/<파일명>` 입니다.

`python prepare_handoff.py` 가 `전달/` 을 만듭니다. 조건이 바뀌면 `--traits` 로 다시 돌립니다.

| 파일 | 내용 |
|---|---|
| `style-01-traits.webp`, `style-02.webp` ~ `style-08.webp` | 채택 조건의 예시 8장 |
| `handoff.csv` | 번호, `name`, `art_style_id`, 조건, 파일, URL, 크기, sha256 |
| `ADGEN_ART_STYLES.json` | **1단계본.** `exampleImageUrl` 이 빈 문자열 |
| `ADGEN_ART_STYLES.filled.json` | **2단계본.** URL 이 채워진 것 |

### 파일 이름은 원본 것을 그대로 씁니다

`style-{NN:02d}{suffix}.webp` 이고 `suffix` 는 조건이 "특징 포함" 일 때만 `-traits` 입니다
(05 제안, 2026-08-22). 1번만 접미어가 붙는 것은 규칙이 달라서가 아니라 **조건이 달라서**이고,
그 접미어가 `artStyleId` 가 1번만 다른 것과 같은 사실을 가리킵니다. 가지런히 고치면 나중에
"이 그림이 어느 조건이었나" 를 다시 물어야 합니다.

**URL 도 이 이름을 정규화 없이 그대로 씁니다.** `exampleImageUrl` 은 설정에 문자열로 박히는
값이라 규칙에서 유도되지 않고, 그래서 정규화의 이득이 생기지 않습니다. 파일명과 URL 이 같은
문자열이라야 `handoff.csv` 한 장으로 눈에 대조됩니다.

두 자리 0채움이 중요합니다. `style-1` 이면 사전순이 `1, 10, 2` 가 되는데 **이 번호가 곧
4 x 2 격자 순서**라, 순서가 어긋나면 사용자가 고른 칸과 프롬프트에 실리는 값이 갈립니다.

### JSON 이 두 벌인 이유

05 가 두 단계로 넣기로 했습니다. **파일이 볼륨에 들어가기 전에 URL 을 채우면 카드가 404 를
그립니다.** 빈 문자열이면 `ArtStylePicker` 가 "예시 준비 중" 자리를 잡으므로(#179), 순서를
뒤집으면 화면이 더 나빠집니다.

1. 지금: `ADGEN_ART_STYLES.json`(빈 URL)으로 8종 격자와 선택을 먼저 살립니다
2. 파일을 볼륨에 넣은 뒤: `ADGEN_ART_STYLES.filled.json` 으로 교체합니다

**`art_style_id` 를 손으로 옮겨 적지 않습니다.** 이미지를 실제로 만든 문자열을
`manifest.csv` / `manifest-traits.csv` 에서 읽습니다 - 이 파일이 존재하는 이유의 절반이
그것입니다. sha256 을 함께 적는 것은 공유 드라이브를 거치면서 파일이 바뀌지 않았는지
받는 쪽이 확인하기 위함입니다.

### PNG 원본을 그대로 넘기지 않습니다

원본은 1152 x 1152 PNG 로 장당 약 2MB 이고 **8장이면 15.8MB** 입니다. 그리고 이것은
화풍 선택 화면(4 x 2 격자)에 8장이 한꺼번에 걸리는 그림입니다.

크기는 1152 px 그대로 두고 WebP 로만 다시 인코딩하면 **합계 1.0MB** 가 됩니다(품질 82,
실측 15.8 -> 1.0MB). 해상도를 깎지 않은 이유는 확대 보기(`.art-zoom`, 최대 560 CSS px)가
고밀도 화면에서 두 배를 쓰기 때문이고, 크기별로 파일을 나누지 않은 이유는 계약의
`ArtStyle` 에 `exampleImageUrl` 이 하나뿐이기 때문입니다.

## 판정이 닫지 못한 것 (의견 수렴 진행)

판정은 **조건 A/B 중 어느 쪽을 채택할지**만 물었습니다. 그 물음이 닫지 못한 것 셋을
`build_opinion_sheet.py` 가 따로 묻습니다. 배치는 `의견수렴/` 이고 판정자 세 분에게
같은 방식으로 넘깁니다.

⚠️ **1번과 2번이 갈렸는지는 아직 확인된 적이 없습니다.** 위 "1번과 2번이 겹칩니다" 절에서
"1 에 특징을 붙이면 갈립니다" 로 닫았는데, **판정 시트는 화풍마다 `가`/`나` 두 장만 보여
줬고 서로 다른 화풍을 나란히 놓은 적이 없습니다.** 자유 응답에서 나온 추론을 수행자가
결론으로 옮겨 적은 것입니다. 그래서 의견 수렴 양식은 **1번과 2번을 지목하지 않습니다** -
지목하면 원하는 답이 나옵니다.
