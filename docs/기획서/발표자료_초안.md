## 02. 무엇을 만들었나 (추가 제안, 1분)

**글과 사진을 넣으면, 브랜드 톤의 광고 소재가 나옵니다.**

- 입력: 제품과 브랜드 정보(글) + 제품 사진, 레퍼런스 이미지
- 출력: 만화형(6칸 3x2 한 장, 3456 x 2304) 또는 단일 광고형(1088 x 1088), 카피 포함

**발표 노트**: 전개 1로 바로 들어가기 전에, 심사자가 30초 안에 "이 서비스가 무엇인지"를

**들어갈 사진/화면**: 만화형과 단일 광고형 예시를 나란히 배치 -

## 03. 왜 만화인가 (전개 1, 1.5분)

> **핵심 문장**: 잘 만드는 싸움이 아니라, 다른 것을 만드는 싸움으로 옮겼습니다.

기존 AI 광고 도구(Canva Magic Design, AdCreative.ai 등)는 성능이 검증된 정적 이미지와
템플릿 도구입니다. 같은 형식으로는 경쟁이 성립하지 않습니다. 그래서 "광고"라는 목적은
유지하고, 결과물의 형식을 만화로 바꿨습니다.

**근거 4축** (검증 7순위 산출물, 주장마다 신뢰도 라벨 첨부)

- 시장 포화 - 정적 배너 광고의 회피 수준이 높다는 매체 비교 연구
- 스토리텔링 효과 - 스토리가 있는 광고가 제품 기억, 광고 태도, 구매 의도에서 앞선다는 연구
- 제작비 장벽 - 캐릭터 외주 건당 평균 약 9만 원, 소재마다 재발주해야 하는 구조
- 유통 채널 적합 - 6칸 3x2가 인스타그램 그리드와 캐러셀 포맷에 맞고, 칸 1152px 고정 크롭이
  성립

**발표 노트**: "왜 만화인가"는 예상 질문 1순위라 검증 과제(7순위)로 등록해 조사했고, 그
산출물이 회의록으로 확정된 상태입니다. 질문이 오면 이 4축을 그대로 답하면 됩니다.
소상공인 대상 실증 사례는 못 찾았다는 한계도 문서에 적혀 있으니, 물으면 숨기지 말고 그대로
말하는 편이 안전합니다.

**들어갈 사진/화면**: 컷별 생성이 그리드 규격에 정확히 맞는 실측 예시 -
`API생성_시험_예시_이미지/컷별생성_운영경로_medium.jpg` (칸 1152x1152 정확, 여백 0px).
인스타그램 그리드/캐러셀 형태 목업은 저장소에 없어 별도 제작 필요.

**근거**: [만화형_채택_근거.md](../기술문서/만화형_채택_근거.md), [기획서.md](기획서.md) 2절,

## 04. 시연 (전개 1, 3분 - 10분 경로에서는 2분)

**진행 방식 확정 (08-27, PM)**: 생성에 시간이 걸려 **사전 녹화 영상**으로 진행합니다. 실기
시연과 실기/녹화 혼합안은 채택하지 않습니다.

> **[영상 삽입 자리]**
> PPT 슬라이드 04에 이 자리에 동영상 개체를 직접 삽입합니다(링크가 아니라 파일 임베드 -
> 발표장 네트워크에 의존하지 않기 위함). 권장 길이 2 ~ 3분, 아래 5단계 시나리오를 그대로
> 담습니다. 발표자는 재생 중 라이브로 내레이션합니다.

**영상에 담을 시나리오** (배포 스택, 실물 모드)

1. 로그인 -> 새 세션에서 제품 정보와 사진 입력
2. 브리프 자동 채움 확인 (판단이 서지 않는 값은 서비스가 되물어 옵니다)
3. 시안(카피 + 6칸 스토리보드) 확인, 마음에 안 드는 자리만 부분 재생성
4. 확정 -> 렌더 시작 (컷별 6칸 생성 후 3x2 합성)
5. 결과 화면 확인, 이미지 다운로드

**녹화 소재**: 08-26 실물 검증 산출물(6칸 대사, 3456 x 2304, 다운로드까지 통과)이 이미
있어 그대로 쓸 수 있습니다. 새로 녹화한다면 실물 모드 키 회수 기한(08-28) 전에 마쳐야
합니다.

**폴백**: 발표장에서 영상 재생이 안 될 경우를 대비해, 같은 산출물의 정지 스크린샷 세트를
별도 슬라이드(숨김)로 준비해 둡니다. 재생 실패 시 그 스크린샷으로 넘어가며 말로 설명합니다.

**08-27 갱신**: 잔여 예산은 QA 몫 10 USD가 합쳐져 약 12.5 USD(만화형 medium 세트당 약
0.40 USD 기준 약 31세트 분량)로 늘었습니다. 녹화를 다시 찍어야 할 경우의 여유가 원문보다
커졌습니다. N22(스텁에서 만화형 처리)는 08-27 회의가 "가/라 프로토타입 비교로 TL이
결정"하기로 정했고, 아직 결과는 안 나왔습니다 - 다만 녹화본을 쓰기로 했으므로 N22가 언제
닫히든 시연 슬라이드 자체는 막히지 않습니다.

**들어갈 사진/화면**: 위 5단계를 담은 사전 녹화 영상(신규 제작 또는 08-26 산출물 재사용).
화면 문구는 08-25 확정된 "HAPPY 3팀"이 반영된 뒤 촬영할 것. 폴백용 정지 이미지는

결과 화면을 재사용.

## 05. 시연이 지나간 길 (추가 제안, 축약 시 생략, 0.5분)

- 프론트엔드 -> 백엔드(세션, 잡, 렌더 배경 작업) -> AI 엔진(생성, 가드레일) -> 외부 이미지
  생성 API
- 두 앱의 결합은 HTTP 계약(`openapi.yaml`) 하나 - 구현보다 계약이 먼저라는 원칙으로 3주를
  지켰습니다
- 만화형: 1번 칸을 먼저 생성 -> 나머지 5칸이 1번 칸을 참조해 동시 생성 -> 3x2 합성
- 가드레일: 입력에 없는 효능, 수치, 수상 이력은 쓰지 않도록 프롬프트로 지시하고, 출력에서
  검출하면 1회 재생성합니다 - 광고이므로 표시광고법이 걸리는 자리입니다

**발표 노트**: 시간이 밀리면 이 장은 15초 말 요약으로 넘어갑니다. 다이어그램 한 장으로
만들면 질의응답 때 되짚는 용도로도 씁니다.

**들어갈 사진/화면**: [아키텍처.md](../공통_가이드/아키텍처.md) 1절 mermaid 다이어그램을
PNG로 내보내 그대로 사용.

- 왜 만화인가 -> 슬라이드 03의 4축 근거로 답합니다
- 왜 파인튜닝을 안 했나 -> 학습 데이터의 출처와 권리 범위가 확보되지 않았고, 기록 없는
  데이터로는 배포 판단을 내리지 않기로 했습니다(ADR-0004)
- 가드레일이 실제로 잡는가 -> 절대값과 표본 수로 답하고, 거짓 양성 한계까지 함께 말합니다

노트로만 남기는 것도 고려.
