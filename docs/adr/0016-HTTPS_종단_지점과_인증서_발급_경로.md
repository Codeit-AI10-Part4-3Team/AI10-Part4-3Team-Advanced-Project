# ADR-0016: HTTPS 는 앞단 프록시에서 종단하고, 인증서는 빌려온 이름으로 받습니다

- **상태**: Accepted
- **날짜**: 2026-08-18 (제안) / 2026-08-19 (확정과 구현)
- **결정자**: 임동규 (05 백엔드/인프라). 이 항목은 미결정 대장이 아니라
  [API_계약.md](../기술문서/API_계약.md) 8절 표에 있어 소관자 결정으로 닫힙니다 (아래 "결정").
  02(TL), 01(PM) 리뷰는 이 결정을 담은 PR 에서 받습니다
- **관련**: [ADR-0008](0008-로그인_수단과_스켈레톤_범위.md),
  [ADR-0011](0011-배포_환경_스펙과_권한_경계.md),
  [ADR-0013](0013-로그인_토큰_형식과_폐기_정책.md),
  [API_계약.md](../기술문서/API_계약.md) 2절, 8절 표, 8.3절, 8.4절, **8.5절(이 결정의 계약 쪽 기록)**,
  [GCP_VM_사용_가이드.md](../공통_가이드/GCP_VM_사용_가이드.md) 2-b절,
  [infra/README.md](../../infra/README.md)

## 배경

2026-08-18 에 워킹 스켈레톤 스택이 VM 에 올라갔습니다. 스택 자체는 정상입니다. 프론트엔드가
80 에서 응답하고, backend 가 계약의 경로 16 개를 전부 서빙하며, ai-engine 8100 은 밖에서 닫혀
있습니다. **그런데 브라우저에서 로그인이 성립하지 않습니다.**

실측한 증상은 이렇습니다. 로그인 요청 자체는 성공해서 서버가 200 과 `Set-Cookie` 를 보내고
화면도 스튜디오로 넘어갑니다. 그러나 새로고침하면 로그인 화면으로 돌아옵니다. 화면이 로그인
상태로 넘어가는 근거가 쿠키가 아니라 응답 본문이기 때문이고(`AuthProvider.signIn`), 마운트
시점의 `GET /v1/me` 가 401 을 받아 진짜 상태가 드러납니다.

원인은 코드가 아니라 앞단입니다. 세션 쿠키는 계약대로 `Secure` 를 달고(ADR-0013), 브라우저는
평문 HTTP 응답에서 `Secure` 쿠키를 저장하지 않습니다.
[API_계약.md](../기술문서/API_계약.md) 8.3절이 2026-08-13 에 예고한 상태가 그대로 재현된
것입니다.

### 이미 정해져 있어 우리가 고를 수 없는 것

- **HTTPS 자체는 미정이 아닙니다.** 미정인 것은 방식뿐이고, 소관은 05, 기한은 "배포 전"입니다
  ([API_계약.md](../기술문서/API_계약.md) 8절 표와 8.3절). 기한이 지금 도래했습니다.
- **`Secure` 를 끄는 설정값은 두지 않습니다** (8.3절). 로그인이 비밀번호를 보내므로(ADR-0008)
  평문 구간이 있으면 자격 증명이 그대로 노출되고, 끄는 스위치는 "잠깐만" 꺼둔 채로 배포됩니다.
- **프론트엔드와 backend 는 같은 출처여야 합니다.** 나뉘면 `SameSite=Lax` 로는 쿠키가 실리지
  않아 `SameSite=None` 과 CORS 가 함께 따라옵니다 (8.3절).
- **게이트웨이 상한은 앱 상한보다 커야 합니다** (2절). 시안 생성의 서버측 상한이 60초이고,
  프론트 nginx 는 이미 120초로 맞춰 두었습니다.
- **결제 계정 권한이 없습니다** (ADR-0011). 도메인 등록과 관리형 로드밸런서가 여기서 빠집니다.
- **외부 IP 주소와 프로젝트 ID 는 저장소에 적지 않습니다**
  ([GCP_VM_사용_가이드.md](../공통_가이드/GCP_VM_사용_가이드.md) 2-b절). 저장소가 public 입니다.
- **저장소에 도메인 기록이 0건입니다.** 실측 기록이 유일한 근거이므로(ADR-0011) 등록된 도메인은
  없는 것으로 봅니다. 고정 IP 는 예약되어 있습니다.

### 한 가지 사실이 바뀌었습니다

[API_계약.md](../기술문서/API_계약.md) 2절은 "현재 스택에는 프록시가 없습니다" 라고 적고
있습니다. **2026-08-15 에 프론트엔드 nginx 가 들어오면서 프록시는 이미 생겼고**, 한 출처로
묶는 역할과 게이트웨이 상한까지 맡고 있습니다. 따라서 남은 결정은 "리버스 프록시를 둘지" 가
아니라 **인증서를 어디서 받아 어디에 물릴지**입니다. 그 문장은 이 ADR 과 함께 고칩니다.

## 선택지

| 안 | 무엇 | 장점 | 단점 |
|---|---|---|---|
| **A. 앞단 프록시 + 빌려온 이름** | Caddy 를 프론트 nginx 앞에 두고, `sslip.io` 류의 이름으로 Let's Encrypt 인증서를 자동 발급 | 정식 인증서라 경고창이 없음. 비용 0. 재현 절차가 학원 환경 안에 남음. 인증서 갱신이 자동 | 외부 DNS 서비스에 의존. **발급 한도를 전 세계 사용자와 공유합니다**(아래 실측). 호스트명 자체가 외부 IP 라 커밋 대상이 아님 |
| B. 자체 서명 인증서 | 프록시에 자체 발급 인증서를 물림 | 외부 의존 0. DNS 불필요 | **시연 첫 화면이 경고창입니다.** 사용자가 매번 "위험을 무릅쓰고 계속" 을 눌러야 하고, 제출물의 첫인상이 그것입니다 |
| C. VM 밖에서 종단 | 터널 서비스가 HTTPS 주소를 제공 | 방화벽을 건드리지 않음. 경고창 없음 | 계정과 외부 서비스가 새로 들어오고 **재현 절차가 학원 환경 밖으로 나갑니다.** ADR-0011 이 선택지 C 를 뺀 것과 같은 이유입니다. 무료 임시 주소는 재시작마다 바뀝니다 |
| D. 도메인을 등록해서 정식 발급 | 이름을 사서 A 레코드를 걸고 발급 | 가장 표준적. 주소가 사람이 읽을 수 있음 | **결제 권한이 없습니다** (ADR-0011). 개인 결제로 우회하는 방향은 ADR-0011 이 이미 기각했습니다 |

## 결정

**A 를 택합니다.** Caddy 를 프론트엔드 nginx 앞에 두어 거기서 TLS 를 종단하고, 인증서는
`sslip.io` 류의 빌려온 이름으로 Let's Encrypt 에서 자동 발급받습니다.

근거는 넷입니다.

1. **경고창 없는 인증서가 제출물의 요건에 가깝습니다.** B 는 이 한 가지 때문에 탈락합니다.
   시연에서 첫 화면이 경고라면 나머지를 다 만들어도 그 인상이 남습니다.
2. **재현 절차가 학원 환경 안에 남습니다.** 컨테이너 하나가 느는 것뿐이라, ADR-0011 이 경계한
   "권한이 없을 때를 가정한 우회 구성" 에 해당하지 않습니다. C 는 여기서 걸립니다.
3. **결제가 필요 없습니다.** D 는 우리 권한 밖입니다.
4. **06 의 `nginx.conf` 를 건드리지 않습니다.** 그 파일에는 IPv6 헬스체크 함정과 게이트웨이
   상한이 이미 반영되어 있고, 소유자가 다릅니다. 앞에 한 겹 얹는 쪽이 되돌리기도 쉽습니다.

이 항목은 [미결정_대장](../기술문서/미결정_대장.md)의 번호 있는 항목이 아니라
[API_계약.md](../기술문서/API_계약.md) 8절 표에 있는 항목입니다. 따라서 확정 근거는 회의록이
아니라 소관자의 결정이며(기획서 14.3 의 대상이 아닙니다), 이 ADR 과 8절 표 갱신으로 닫습니다.

## 결과

### 생기는 제약

- **호스트명은 설정값입니다.** `<외부 IP>.sslip.io` 형태라 그 문자열 자체가 외부 IP 이고,
  커밋하면 [GCP_VM_사용_가이드.md](../공통_가이드/GCP_VM_사용_가이드.md) 2-b절 위반입니다.
  값은 `infra/.env`(gitignored)에 두고 `.env.example` 에는 이름만 둡니다. `ADGEN_ACCOUNTS` 의
  argon2 해시를 다루는 방식과 같습니다.
- **로컬과 배포가 같은 compose 파일을 씁니다.** 호스트명이 비어 있으면 Caddy 는 `:80` 평문으로
  뜨고, 값이 있으면 자동으로 HTTPS 를 켭니다. 배포 전용 override 파일을 만들지 않으므로
  `docker-build.yml` 의 `-f` 목록에 빠뜨리는 함정(compose 파일 머리말)도 밟지 않습니다.
- **방화벽 규칙 1건이 필요합니다.** 443 을 엽니다. 규칙 생성 권한은 2026-08-10 실측으로
  확인되어 있습니다 ([infra/README.md](../../infra/README.md) 권한 경계 표).
  주의: **80 은 닫지 않습니다.** 인증서 발급 검증이 80 으로 들어옵니다.
- **프론트엔드 nginx 는 게시를 멈추고 내부 전용이 됩니다.** 브라우저가 보는 출처는 Caddy
  하나입니다. 같은 출처라는 성질은 그대로 유지되므로 `SameSite=Lax` 도 그대로입니다.
- **Caddy 의 상한도 앱 상한보다 커야 합니다** (API_계약 2절). 기준은 시안 생성 60초입니다.
  렌더는 잡이라 이 경로로 기다리지 않습니다.
- **인증서는 이름 있는 볼륨에 둡니다.** 컨테이너를 내렸다 올릴 때마다 재발급하면 발급 한도를
  먹습니다. 볼륨을 쓰는 이유는 ADR-0014 와 같습니다.
- **backend 8000 의 게시를 중단합니다.** [infra/README.md](../../infra/README.md) 가 "HTTPS
  종단이 들어올 때 닫을지 함께 정한다" 고 예고한 항목입니다. 닫는 쪽을 택하는 이유는, 열어 두면
  로그인 비밀번호를 평문으로 받는 문이 하나 남기 때문입니다(ADR-0008). `curl` 로 계약을 직접
  두드리던 경로는 HTTPS 주소로 그대로 대체됩니다.

### 쉬워지는 것

- **브라우저 로그인이 성립합니다.** 08-17 판정 기준의 "스켈레톤 관통" 이 브라우저에서 실제로
  확인 가능해집니다.
- **인증서 갱신 자동화를 따로 만들지 않습니다.** 발급과 갱신이 프록시 안에 있습니다.
- **계약을 고치지 않습니다.** 이미지 URL 을 앱 상대 경로로 둔 덕분에(API_계약 8.4절) 종단이
  무엇이든 저장된 값이 어긋나지 않습니다. 이 결정은 그 전제를 확인할 뿐입니다.

### 어려워지는 것

- **외부 DNS 서비스에 의존합니다.** 다만 의존하는 시점은 발급과 갱신 때뿐이고, 인증서 수명
  90일은 프로젝트 잔여 기간(08-31 까지)보다 깁니다. 즉 갱신은 프로젝트 안에서 일어나지 않습니다.
- **발급 한도를 전 세계 사용자와 공유합니다 (2026-08-19 확인).** 이 항목은 처음에 "확인 전,
  확신도 중간" 으로 남겨 두었는데, 확인해 보니 나쁜 쪽이었습니다.

  | 확인한 것 | 결과 |
  |---|---|
  | Public Suffix List 에 `sslip.io` 가 있는가 | **없습니다.** 원본 16,423줄을 받아 검색해 0건 (`nip.io` 도 0건). 대조군 `github.io` 는 13,789행에 있어 파일은 온전합니다 |

  등재돼 있으면 이름마다 한도가 분리되는데 없으므로, Let's Encrypt 가 보는 registered domain 은
  `<외부 IP>.sslip.io` 가 아니라 **`sslip.io` 하나**입니다. 즉 "Certificates per Registered
  Domain 50/week" 이 그 이름을 쓰는 전 세계 사용자에게 하나로 걸립니다.

  실패는 Caddy 로그에 즉시 드러나고, 그때는 B 로 내려간 뒤 이 ADR 을 갱신합니다.
  **ZeroSSL 폴백을 남겨 둔 이유가 이것입니다** - `acme_ca` 를 지정하면 발급자 목록이 그 ACME
  하나로 대체되어(2026-08-19 실측) 두 번째 시도가 사라집니다. 그래서 지정하지 않았습니다.

- **발급 검증이 실패하면 시간당 5회에서 잠깁니다.** Let's Encrypt 의 failed validation 한도이며,
  위의 인증서 한도와 별개입니다. 다만 그 검증이 보는 두 가지는 미리 쟀습니다.

  | 확인한 것 (2026-08-19) | 결과 |
  |---|---|
  | 공개 DNS 가 그 이름을 VM 의 외부 IP 로 푸는가 | 하이픈 형식과 점 형식 **둘 다 일치** |
  | 80 이 밖에서 닿는가 | 닿습니다 (0.2초에 연결) |

  둘 다 맞으므로 staging 엔드포인트를 먼저 밟는 절차는 넣지 않았습니다. staging 이 확인해 주는
  것이 정확히 이 둘이고, **공유 한도는 staging 으로 확인할 수 없습니다**(한도가 분리되어 있기
  때문입니다). 첫 시도가 검증 단계에서 실패하면 그때 staging 으로 내려가 원인을 가릅니다.
- **홉이 하나 늘고 컨테이너가 하나 늡니다.** 장애 지점이 하나 추가되며, 헬스체크와 로그를 볼
  곳이 늘어납니다.
- **주소를 사람이 외우기 어렵습니다.** IP 가 이름 안에 들어가 있기 때문입니다.

### 재검토 신호

- **발급이 한도로 실패하면** B 로 내려가고 이 ADR 을 Superseded 로 바꿉니다. 한도를 전 세계와
  공유한다는 것이 확인됐으므로(위) 이 신호는 가정이 아니라 실제 가능성입니다.
- **도메인이 생기면** 호스트명 설정값만 바꿉니다. 구조는 그대로이므로 A 를 유지합니다.
- **Let's Encrypt 의 IP 주소 인증서를 프록시가 지원하는 것이 확인되면** 빌려온 이름과 외부 DNS
  의존을 함께 없앨 수 있습니다. 다만 그 인증서는 수명이 짧아 갱신이 제출 주간에 여러 번 돌아야
  하므로, 갱신 실패의 비용이 의존을 없애는 이득보다 큰지 함께 봅니다.
- **프론트엔드와 backend 가 다른 출처로 나뉘면** `SameSite=None` 과 CORS 가 함께 열리며,
  그때 HTTPS 는 선택이 아니라 전제가 됩니다 (API_계약 8.3절).
- **프록시 앞에 관리형 계층(로드밸런서, CDN)이 들어오면** 종단 지점이 옮겨가므로 이 ADR 을
  다시 엽니다.
