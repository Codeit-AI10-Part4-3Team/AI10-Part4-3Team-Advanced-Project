# 06. 프론트엔드 — 송기하

> 일정은 [역할_일정/06-프론트엔드.md](../역할_일정/06-프론트엔드.md)에 있습니다.
> 담당자 배정 시 이 제목과 [README.md](README.md)의 표, `CODEOWNERS`를 함께 채우세요.

## 한 줄 정의

이 역할이 없으면 **사용자가 쓸 수 있는 상태**가 되지 않습니다. curl로만 검증된 것은 서비스가 아닙니다.

## 소유 경로

`CODEOWNERS`와 **같은 경로**여야 합니다. 다르면 리뷰 자동 배정이 엉뚱한 사람에게 갑니다.

- `apps/frontend/`

## 책임

- 제품 정보 입력 + 레퍼런스 이미지 업로드 화면을 만든다
- 생성이 수십 초 걸린다는 사실을 UI로 다룬다 — 진행 상태 표시, 이탈 후 복귀
- 결과 갤러리와 다운로드를 제공한다
- 폴백으로 응답한 결과를 **일반 결과와 구분되게** 표시한다 (그 표기를 지우면 열화 경로가 은폐됩니다)
- 스캐폴딩 전에 `apps/frontend/README.md`의 함정과 루트 `.gitignore`의 `lib/` 패턴을 먼저 읽는다

## 하지 않는 일 (경계)

책임보다 이 항목이 분쟁을 더 많이 막습니다.

- 모델 직접 호출 (backend 경유. 프론트에 키가 들어가면 public 저장소에서 즉시 유출입니다)
- 계약 변경 (02와 합의 후 `openapi.yaml`이 먼저)

## 산출물

| 산출물 | 위치 | 완료 판단 기준 |
|---|---|---|
| 입력 화면 | `apps/frontend/` | 텍스트 + 이미지 업로드가 잡 생성까지 관통 |
| 진행/결과 화면 | `apps/frontend/` | 탭을 닫았다 열어도 진행 중인 잡을 다시 찾을 수 있음 |
| 폴백 표기 | `apps/frontend/` | 폴백 결과가 시각적으로 구분됨 |
| 프론트 CI 활성화 | `.github/workflows/frontend-ci.yml` | 스캐폴딩 후 자동 활성 (non-required 유지) |

## 인수인계 시 넘겨야 하는 것

이 역할이 빠졌을 때 다음 사람이 곧바로 이어받으려면 무엇이 문서로 남아 있어야 하는가.
**"머릿속에만 있는 것"을 여기에 적고, 그것을 없애는 것**이 이 항목의 목적입니다.

- 디자인 결정 중 코드에 드러나지 않는 것 (왜 이 흐름인가)
- 브라우저·기기별로 확인한 범위와 확인하지 않은 범위
