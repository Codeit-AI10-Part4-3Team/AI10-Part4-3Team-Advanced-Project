# 검증 1순위 - 6칸 조건 한국어 렌더링 (+ 6순위 비용 실측)

기획서 15절 1순위와 6순위를 한 벌의 스크립트로 돌립니다. 원 담당은 임유빈(역할 03)이고,
2026-08-13 시점에 TL(신호정)이 하네스를 대신 준비했습니다. 인계 상태는
[../../../docs/역할_일정/03-AI_생성_서빙.md](../../../docs/역할_일정/03-AI_생성_서빙.md)를 보세요.

## 무엇을 판정하는가

| | 본안 (`--variant main`) | 예비안 (`--variant fallback`) |
|---|---|---|
| 지시 | 말풍선 안에 한국어 대사까지 그린다 | 말풍선만 그리고 글자는 비운다 |
| 성공 | 칸의 대사가 정답과 글자 단위로 같음 | 말풍선 안에 글자가 하나도 없음 |
| 뒤집히면 | - | 합성 단계와 폰트 자산이 새로 필요 |

**두 갈래를 같은 회차에서 확인합니다.** 나중에 따로 돌리면 조건이 달라져 비교가 성립하지
않습니다 (미결정_대장 A-1).

합격 기준은 B-16(검증 합격 판정 기준 수치)에서 확정된 값입니다: **20회 생성에서 6칸 중 5칸
이상의 대사가 오탈자 없이 표기되는 비율 80% 이상**. 첫 10회 결과를 보고 조정할 수 있습니다.

## 조건 (바꾸면 이전 회차와 비교가 깨집니다)

- 해상도 **3456 x 2304**, 칸당 1152 x 1152, 3 x 2 격자. **정사각 한 장으로 재지 마세요** -
  실제보다 유리한 결과가 나옵니다 (기획서 15절).
- 시나리오와 정답 대사 6개는 `conditions.py`에 고정되어 있습니다. 대사 길이는 6자 ~ 14자로
  본안에 유리한 쪽입니다. 여기서 떨어지면 더 긴 대사에서는 확실히 떨어집니다.
- 프롬프트에 근거 기반 생성 지시가 들어 있습니다. 빼면 실제 파이프라인의 프롬프트와 달라져
  실험 결과를 그대로 이전할 수 없습니다.

## 실행

```bash
pip install -r requirements.txt
export ADGEN_MODEL_API_KEY=...          # infra/.env 에 두고 export. 절대 커밋하지 말 것

python run_experiment.py --dry-run                    # 프롬프트만 확인, 호출 없음
python run_experiment.py --runs 1                     # 스모크 1회 = 6순위 단가 실측
python run_experiment.py --runs 20 --yes              # 본 회차 (본안)
python run_experiment.py --runs 20 --variant fallback --yes
```

**반드시 `--runs 1`을 먼저 돌리세요.** 요청 해상도가 거절되는지, 응답에 usage가 실리는지,
1회당 얼마인지가 여기서 드러납니다. 기본값이 1인 것도 같은 이유입니다 - 오타 한 번이 20회
호출이 되면 안 됩니다.

비용 열은 요금표를 넣었을 때만 채워집니다:

```bash
export ADGEN_PRICE_INPUT_PER_MTOK=5.00    # gpt-image-2 text input
export ADGEN_PRICE_OUTPUT_PER_MTOK=30.00  # gpt-image-2 image output
```

넣지 않으면 토큰 수만 남습니다. **추정 단가를 실측이라고 적지 않기 위해서입니다** - 이 숫자가
PM의 실험 예산 상한 근거가 됩니다 (구현_범위 4.2절).

위 값은 2026-08-13에 [OpenAI 요금표](https://developers.openai.com/api/docs/pricing.md)에서
확인한 것입니다: text input $5.00 / image input $8.00 / image output $30.00 (100만 토큰당).

> 주의: 스크립트는 `input_tokens`에 text 단가를 곱합니다. 지금 실험은 텍스트만 입력하므로
> 맞지만, **레퍼런스 이미지나 제품컷을 입력에 넣기 시작하면 image input($8)이 섞여 과소
> 계산됩니다.** 4순위(IP-Adapter)나 제품컷 입력을 실험할 때는 `calls.jsonl`의
> `input_tokens_details`로 갈라서 계산하세요.

### 세션당 단가 (6순위 완료 조건)

6순위가 요구하는 것은 호출당이 아니라 **세션당** 단가입니다. 위에서 나온 호출당 단가에 세션
1회의 호출 구성을 곱하세요:

| 이음매 | 호출 | 비고 |
|---|---|---|
| `brief:fill` | 텍스트 1회 | 사진 판독 포함 |
| `draft:generate` | 텍스트 1회 | 가드레일 위반 시 재생성 1회까지 (생성_파이프라인 5.1.1) |
| `image:render` | 이미지 1회 | 만화형이면 이 실험의 단가 그대로 |

재생성 1회를 포함한 최악값을 함께 적으세요. 평균만 적으면 상한의 근거가 되지 못합니다.

## 대사 길이 구간 회차 (`--variant mid`) - N18

**무엇을 재는가**: 몇 자부터 오탈자가 나오는가. 미결정_대장 N18(대사 길이 상한)이 빈 구간
때문에 닫히지 않고 있고, 그 구간을 메우는 회차입니다.

```bash
python run_experiment.py --variant mid --dry-run     # 프롬프트와 대사 확인
python run_experiment.py --variant mid --runs 1      # 스모크
python run_experiment.py --variant mid --runs 20 --yes
```

**길이만 움직입니다.** 시나리오, 장면 지시, 격자, 화풍, 근거 문장이 전부 `main` 과 같고
순한국어입니다. `hard` 회차는 길이와 영어/숫자를 함께 올려서 **무엇 때문에 틀렸는지 갈라낼 수
없었습니다** - 그래서 별도 회차입니다.

| 칸 | 길이 | 대사 |
|---|---|---|
| 1 | 15자 | 아침부터 커피를 또 쏟았네. |
| 2 | 17자 | 이럴 때 쓰려고 미리 사 뒀지. |
| 3 | 19자 | 두꺼운 원단이라 한 장이면 충분해. |
| 4 | 21자 | 닦고 나니 냄새도 자국도 안 남는구나. |
| 5 | 23자 | 무향 무알코올이라 아이가 써도 안심이네요. |
| 6 | 25자 | 순한 대나무 물티슈로 매일을 산뜻하게 지내요. |

**한 회차가 여섯 길이를 동시에 잽니다.** 그래서 판정 시트의 네 번째 열이 `main` 과 다릅니다 -
`6칸 균등 분할` 대신 **`틀린 칸 번호`** 이고, 이 회차에서는 참고용이 아니라 필수입니다. 칸 수만
있으면 "몇 칸이 틀렸는가"는 알아도 **"어느 길이가 틀렸는가"**를 알 수 없습니다.
`score_sheet.py tally` 가 칸 번호를 길이로 되붙여 길이별 표를 출력합니다.

**두 열이 서로 어긋나는 회차는 길이 집계에서 빠집니다** (칸 수 6인데 번호가 적혀 있거나,
칸 수 4인데 번호가 하나뿐인 경우). 어느 쪽이 맞는지 알 수 없는데 그대로 세면 없는 실패가
생기거나, 빠진 칸이 정상 표본으로 들어가 **상한이 실제보다 높게** 잡히기 때문입니다.
`tally` 가 어느 시트의 몇 번 회차인지 찍어 주므로 그 판정자에게 다시 물어보세요.

### 자릿수 세는 규칙 (2026-08-20 정정)

**`len()` 으로 셉니다 - 공백과 문장부호를 포함합니다.** 상한이 정해지면 그것을 집행하는 쪽은
`draft:generate` 의 검사 코드이고, 코드가 셀 수 있는 정의라야 상한이 집행됩니다.

⚠️ **이 기준으로 다시 세면 문서에 적힌 숫자 몇 개가 틀렸습니다.** 실험 당시 커밋
(`a5e7ee3`, `c7801ad`)의 문자열을 직접 센 값입니다.

| 어디 | 적혀 있던 값 | 실제 |
|---|---|---|
| 1순위 대사 구간 | 6 ~ 14자 | **9 ~ 15자** (2번 칸이 15자) |
| `hard` 의 긴 대사 | 27자 | **30자** |

**결과가 달라집니다.** 15자에는 이미 20회 표본이 있고(오탈자 0건), 관측된 실패는 30자입니다.
따라서 진짜 빈 구간은 **16 ~ 23자와 25 ~ 29자**이며, 위 대사 세트가 그 앞쪽을 덮습니다.

### 한계

- **길이가 칸 위치와 묶여 있습니다.** 회차를 늘려도 "25자가 어렵다"와 "6번 칸이 어렵다"가
  갈라지지 않습니다. 1순위에서 120칸 전부 무오탈자였으므로 위치 효과는 작다고 보고 감수했지만,
  결과가 6번 칸에만 몰리면 길이를 칸에 섞어 다시 돌려야 합니다.
- **`quality` 를 `main` 회차와 맞춰야 비교가 성립합니다.** 1순위는 `quality` 미지정으로
  돌았습니다. 티어가 글자 렌더링에 영향을 준다면 길이 효과와 섞입니다.

## 판정

```bash
python score_sheet.py build --run-dir runs/<타임스탬프>-main --judges 정승호 임동규 송기하
# 시트와 이미지를 판정자에게 전달 -> 채워서 회수 -> 같은 폴더에 되돌려 놓고
python score_sheet.py tally --run-dir runs/<타임스탬프>-main
```

- **실험을 돌린 사람은 판정자에서 제외합니다** (기획서 15절). 2026-08-13 회차는 TL이 돌렸으므로
  TL을 뺀 사람이 판정합니다.
- 이미지는 커밋하지 말고 팀 공유 드라이브로 올리세요. `runs/`는 `.gitignore`에 걸려 있습니다.
- **수치를 옮길 자리는 판정 종류마다 다릅니다** (아래 표). 여기에만 두면 없었던 실험이 됩니다
  (구현_범위 4.3절).

### `--task` 로 판정 종류를 고릅니다

시트의 열이 서로 다르고 파일 이름도 갈라 두었습니다. **같은 회차 폴더를 다시 쓰는 설계라 이름이
같으면 이미 채워진 판정을 덮어씁니다.**

| `--task` | 검증 | 묻는 것 | 시트 파일 | 수치를 옮길 곳 |
|---|---|---|---|---|
| `text` (기본) | 1순위 | 대사가 정확히 표기되는가 | `sheet-<판정자>.md` | 미결정_대장 A-1 |
| `consistency` | 3순위 | 인물과 화풍이 6칸에서 유지되는가 | `consistency-<판정자>.md` | 미결정_대장 A-4 |
| `style` | 5순위 | 지정한 화풍이 결과에 반영되는가 | `style-<판정자>.md` | 미결정_대장 A-3 + 5순위 보고서 |

3순위는 1순위 이미지를 그대로 다시 보므로 **추가 생성이 없습니다.** 5순위는 다릅니다 -- 회차마다
화풍이 달라야 성립하므로 **전용 회차가 필요하고, manifest 에 `art_style_id` 열이 있어야
합니다.** 없으면 `build` 가 그 자리에서 멈춥니다 (빈 `지정 화풍` 칸이 든 시트를 판정자에게
보내는 것보다 낫습니다).

```bash
python score_sheet.py build --run-dir runs/<타임스탬프>-style --judges 정승호 임동규 송기하 --task style
python score_sheet.py tally --run-dir runs/<타임스탬프>-style --task style
```

⚠️ **5순위 시트 말미의 `구분되지 않는 화풍이 있습니까` 는 집계되지 않습니다. 직접 읽으세요.**
기획서 15절이 건 기준은 "화풍별 결과가 **구분 가능**할 것"인데, 회차별 Y/N 로는 두 화풍이 서로
닮았는지가 구조적으로 잡히지 않습니다 -- 각 회차가 독립으로 채점되기 때문입니다. 화풍 예시
판정(2026-08-22)에서 판정자 두 분이 1번과 2번이 비슷하다고 독립적으로 적은 것이 정확히 이
경우이고, 그 지적은 표가 아니라 자유 응답에서 나왔습니다.

## 결과로 인정되는 조건 (구현_범위 4.4절)

1. 조건 - 프롬프트, 해상도, 시도 횟수. `runs/<폴더>/prompt.txt`와 `manifest.csv`에 남습니다.
2. 수치 - 성공 비율. `score_sheet.py tally` 출력.
3. 판정자 - 실험을 돌린 사람이 아닌 사람.
4. 결론 - 본안 유지인지 예비안 전환인지. **"더 해봐야 안다"는 결론이 아닙니다.**

## 2026-08-13 실측 (TL, 22회)

| 항목 | 값 |
|---|---|
| 요청 해상도 3456 x 2304 | **그대로 통과.** 기획서 10.2의 규격 표가 실물과 맞습니다 |
| 생성 시간 | 본안 60.4 ~ 83.7초 (평균 69.8), 예비안 39.3 ~ 121.7초 (평균 66.4) |
| 단가 | 본안 $0.1171 고정, 예비안 $0.0502 ~ $0.1148 (평균 $0.0778) |
| 누적 소진 | $2.18 (22장) |

**생성 시간 60 ~ 122초는 설계 결정의 근거가 됩니다.** AGENTS.md의 "이미지 생성은 동기 HTTP
금지, 잡 접수 후 폴링"이 지금까지 근거 없는 판단이었는데 실측치가 붙었습니다. 통상적인
게이트웨이 타임아웃(30 ~ 60초)을 이미 넘깁니다.

### 품질 티어가 요청마다 달라집니다 (조건 고정의 구멍)

`quality`를 주지 않으면 모델이 회차마다 티어를 고릅니다. 예비안 10회에서 출력 토큰이
**1674(6회)와 3826(4회)로 갈렸고 비용이 2.3배 차이**났습니다. 파일 크기도 7.2MB와 9.1MB로
갈립니다. 본안 10회는 전부 3826이었습니다.

- **본안 10회의 1순위 판정은 유효합니다** - 티어가 전부 같았습니다.
- **예비안은 티어가 섞였습니다.** 예비안의 성공 조건("글자가 없는가")이 티어와 무관할
  가능성이 높지만(`추정`), 조건 고정 원칙에는 어긋납니다.
- 다음 회차부터는 `--quality`로 명시하세요. **받는 값이 무엇인지는 아직 확인되지 않았습니다** -
  잘못된 값을 기본값으로 박으면 전 회차가 400으로 죽으므로 기본은 미지정으로 두었습니다.
- 비용 예측에도 걸립니다. 예산 상한은 **높은 티어 기준**으로 잡아야 합니다.

## 알려진 미확인 사항

- `quality` 파라미터가 받는 값과 기본 동작 (위 절).
- 2순위(컷 경계 제어)의 실패 판정 기준은 아직 미배정입니다 (미결정_대장 A-2). 판정 시트가
  균등 분할 여부를 함께 받으므로 **기준이 정해지면 이 회차의 데이터로 소급 판정할 수 있습니다.**
  같은 이미지를 다시 만들 필요가 없습니다.
