# ADR-0010: 상태는 SQLite 파일에, 이미지는 VM 로컬 디스크에 둔다

- **상태**: Accepted
- **날짜**: 2026-08-09
- **결정자**: 신호정 (TL)
- **관련**: [세션_보관_정책.md](../기술문서/세션_보관_정책.md) 2절과 3절, 기획서 13.1, 17.1-3

## 배경

세션 상태(브리프, 시안, 잡)와 파일(업로드 사진, 결과 이미지)을 어디에 둘지 정해야 백엔드 구현이
시작됩니다. 기획서 17.1-3이 "기술문서에서 정할 것"으로 넘긴 항목입니다.

제약은 셋입니다.

- **배포 대상은 GCP GPU VM 1대**입니다 (기획서 13.1). 운영 인원이 따로 없습니다.
- **실작업 22일**입니다. 저장소를 하나 더 세우면 기동, 백업, 접속 정보 관리가 전부 우리 일입니다.
- **동시 렌더는 1건**입니다 ([세션_보관_정책.md](../기술문서/세션_보관_정책.md) 6절).
  쓰기 경합이 구조적으로 낮습니다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. **SQLite 파일 + VM 로컬 디스크** | 운영 대상이 프로세스뿐. 백업이 파일 복사. 재시작을 견딤 | 워커를 늘리면 쓰기 잠금이 문제. VM이 사라지면 데이터도 사라짐 |
| B. Postgres + 오브젝트 스토리지 (GCS) | 확장과 백업이 표준적. VM과 데이터의 수명이 분리됨 | 운영 대상이 셋으로 늘고 키 관리가 추가. 22일 안에 회수되지 않음 |
| C. 인메모리 | 가장 단순 | 재시작하면 진행 중이던 세션이 사라짐. 사용자에게는 "확정을 눌렀는데 결과가 없다"로 보임 |

## 결정

**A를 택합니다.** 상태 저장소는 SQLite 파일, 이미지 파일은 VM 로컬 디스크입니다.

| 대상 | 위치 |
|---|---|
| 계정, 세션, 브리프, 시안, 잡 | SQLite 파일 1개 |
| 업로드 사진, 결과 이미지 | VM 로컬 디스크. DB에는 경로만 |

- **이미지 바이트를 DB에 넣지 않습니다.** SQLite 파일이 수 GB로 불어나면 백업이 파일 복사라는
  장점이 사라집니다.
- **`ai-engine`은 상태를 갖지 않습니다.** 상태를 가지면 재시작마다 진행 중인 잡이 사라지고,
  엔진을 독립 배포 단위로 두는 의미가 없어집니다.
- **보존 기간은 정책이지 이 결정의 일부가 아닙니다.**
  [세션_보관_정책.md](../기술문서/세션_보관_정책.md) 2절이 정본이며, 일 1회 정리 배치가
  실제로 지웁니다. 기간을 문서에만 적어 두면 아무것도 지워지지 않습니다.

C를 택하지 않은 이유는 **유실이 사용자에게 보이기 때문**입니다. 재시작은 배포할 때마다 일어납니다.

B를 택하지 않은 이유는 **얻는 것이 이번 범위 밖이기 때문**입니다. 확장성과 데이터 수명 분리는
사용자가 팀 내부인 동안에는 값을 하지 않습니다 (기획서 11.2). 필요해지는 시점은 아래 재검토
신호에 적어 둡니다.

## 결과

**생기는 제약**

- **워커 프로세스를 여러 개로 늘리지 마세요.** 늘리는 순간 SQLite 쓰기 잠금이 문제가 되고,
  이 결정을 다시 열어야 합니다. 늘리기 전에 ADR을 먼저 고칩니다.
- **VM을 재생성하면 데이터가 사라집니다.** 시연과 발표에 쓸 산출물은 보존 기간과 무관하게
  별도로 내려받아 두세요. 복구 경로는 없습니다.
- SQLite 파일과 이미지 디렉토리의 경로는 **설정값**입니다. 코드에 상수로 박으면 로컬 개발과
  VM 배포가 갈라집니다.
- 백업은 "SQLite 파일 + 이미지 디렉토리" 두 경로의 복사입니다. 정기 백업 여부는 배포 단계
  소관입니다 (기획서 17.2).

**쉬워지는 것**

- 로컬 개발 환경이 VM과 같은 구성입니다. 외부 저장소 없이 전 경로가 돕니다.
- 테스트가 임시 디렉토리 하나로 격리됩니다.

**어려워지는 것**

- 데이터를 옮기려면 이관 스크립트가 필요합니다. B로 넘어갈 때 한 번은 치러야 하는 비용입니다.

**재검토 신호**

- 렌더 워커를 2개 이상으로 늘려야 할 때 (동시 렌더 수 상향).
- 쓰기 경합으로 `database is locked`가 실제로 관측될 때. 추측으로 옮기지 않습니다.
- 외부 공개로 사용자가 팀 밖으로 나갈 때 (기획서 17.2).
