# ADR-0012: 시안 생성이 실패하면 브리프 잠금을 풀고 되돌립니다

- **상태**: Accepted
- **날짜**: 2026-08-10
- **결정자**: 신호정 (TL), 임동규 (05 백엔드) 제안
- **관련**: [ADR-0009](0009-브리프_잠금_시점과_광고_기획안_읽기_전용.md),
  [도메인_모델.md](../기술문서/도메인_모델.md) 7절 INV-7,
  [용어_사전.md](../기술문서/용어_사전.md) 3.1절,
  [API_계약.md](../기술문서/API_계약.md) 0절

## 배경

[ADR-0009](0009-브리프_잠금_시점과_광고_기획안_읽기_전용.md)가 INV-7을 세우면서 브리프를
`draft_generating` 진입과 동시에 잠갔습니다. 그런데 **그 진입이 실패로 끝나는 경우를 다루지
않았습니다.** PR #47 리뷰에서 발견됐습니다.

[용어_사전.md](../기술문서/용어_사전.md) 3.1절의 상태도를 보면 `draft_generating`에서 나가는
간선이 `draft_ready` 하나뿐입니다. `brief_filling`과 `rendering`에는 `failed`로 가는 간선이
있는데 여기만 없습니다.

그래서 시안 생성이 503으로 실패하면 이렇게 됩니다.

1. 세션은 `draft_generating`에 머무릅니다.
2. INV-7이 이미 걸려 브리프를 고칠 수 없습니다.
3. `POST /v1/sessions/{id}/draft`를 다시 부르면 409 `STATE_CONFLICT`입니다.
4. **빠져나갈 경로가 없습니다.** 브리프는 잠겼는데 시안은 없는 세션이 남습니다.

의존이 죽는 것은 드문 일이 아닙니다. 외부 모델 API 장애는 리스크 표에도 올라 있는 항목이고
(리스크 7번), 열화 폴백이 시안 생성에는 없으므로
([ADR-0005](0005-열화_폴백은_자동화_생략으로_한정.md)) 실패는 그대로 사용자에게 닿습니다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. **`brief_ready`로 되돌리고 브리프 잠금도 함께 푼다** | 재시도 경로가 생깁니다. 실패 원인이 입력이면 브리프를 고쳐 다시 시도할 수 있습니다 | INV-7의 문구를 상태 기준에서 산출물 기준으로 다시 써야 합니다 |
| B. `failed`로 보내고 잠금은 유지한다 | INV-7을 그대로 둡니다 | 사용자가 할 수 있는 일이 새 세션을 처음부터 다시 만드는 것뿐입니다. 입력을 전부 다시 넣어야 합니다 |
| C. `draft_generating`에 머무르되 재요청만 허용한다 | 변경이 가장 작습니다 | 같은 브리프로만 재시도됩니다. 실패 원인이 브리프면 몇 번을 눌러도 같은 결과입니다. 상태가 "진행 중"인데 아무것도 진행되지 않는 것도 화면에 거짓말이 됩니다 |

## 결정

**A를 택합니다.** 시안 생성이 실패하면 세션은 `brief_ready`로 되돌아가고, 브리프와 `briefMeta`의
잠금도 함께 풀립니다.

INV-7의 문구를 바꿉니다.

| | 문구 |
|---|---|
| 기존 | `draft_generating` 진입 이후 `brief` 변경 불가 |
| 변경 | **시안이 존재하는 동안** `brief` 변경 불가. `draft_generating` 진입 시 잠기고, 생성 실패로 `brief_ready`에 되돌아오면 풀립니다 |

**이것은 ADR-0009를 뒤집는 것이 아닙니다.** ADR-0009가 브리프를 잠근 이유는 "시안이 브리프에서
나온 산출물이라, 근거가 나중에 바뀌면 시안이 무엇에 근거했는지 알 수 없게 된다"였습니다.
**생성이 실패했다면 시안이 없고, 따라서 보호할 근거 대응 자체가 없습니다.** 문구가 상태를
기준으로 쓰여 있어서 의도보다 넓게 잠겼던 것이고, 이 결정은 그 범위를 의도에 맞춥니다.

B를 택하지 않은 이유는 **사용자가 잃는 것이 크기 때문**입니다. 우리 잘못(의존 장애)으로 실패했는데
사용자가 제품 정보와 사진을 전부 다시 넣어야 합니다. ADR-0009가 C안을 물리치며 쓴 문장이 여기에도
그대로 적용됩니다 -- 막으면 못 한 것이고 폐기하면 잃은 것입니다.

C를 택하지 않은 이유는 **실패 원인이 브리프일 때 답이 없기 때문**입니다.

## 결과

**생기는 제약**

- **롤백은 전부 아니면 전무입니다.** 시안이 한 조각이라도 저장됐다면 되돌리지 않습니다. 시안 생성은
  한 번의 호출로 시안 하나를 통째로 만들거나 아무것도 만들지 않습니다.
- **되돌릴 때 `briefMeta`도 함께 풉니다.** 브리프와 같은 시점에 잠기는 값이므로 따로 두면 한쪽만
  고칠 수 있는 상태가 생깁니다.
- **`outputType`은 풀지 않습니다.** 세션 생성 시 고정이고 시안 실패와 무관합니다.
- 상태 기계 가드는 `draft_generating -> brief_ready` 전이를 **실패 경로에서만** 허용해야 합니다.
  사용자가 임의로 되돌리는 경로를 열어 주는 것이 아닙니다.

**쉬워지는 것**

- 재시도가 화면에서 자연스러워집니다. `brief_ready`는 이미 "마지막 확인 지점"으로 정의된
  화면이라, 실패하면 그 화면으로 돌아오면 됩니다. 새 화면을 만들지 않습니다.

**어려워지는 것**

- 실패 횟수를 세지 않으면 같은 요청이 무한히 반복될 수 있습니다. 상한과 표시 방법은 이 ADR의
  범위가 아니며, 필요해지면 그때 정합니다.

**다루지 않는 것**

- **렌더 실패 후 재시도는 이 ADR의 범위가 아닙니다.** `rendering -> failed` 이후 다시 시도할 수
  있는지는 여전히 미정입니다 (기획서 18.2 #13). 렌더는 INV-3(세션당 1회)이라는 비용 방어선이
  걸려 있어 성질이 다릅니다. 같은 결정으로 묶으면 비용 방어선이 함께 흔들립니다.

**재검토 신호**

- 시안 생성이 부분 성공할 수 있는 구조로 바뀔 때. 그러면 "전부 아니면 전무"라는 전제가 깨집니다.
- 실패 반복이 실제로 관측될 때. 재시도 상한을 이 결정 위에 얹습니다.
