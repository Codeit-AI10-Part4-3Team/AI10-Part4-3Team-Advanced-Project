### 0-8. 값을 어디서 읽는가

**화면에 그대로 보이는 값과 그렇지 않은 값이 갈립니다.** 손으로 적을 것만 적고, 나머지는
실행이 끝난 뒤 로그에서 한 번에 뽑습니다.

| 기록 칸 | 어디서 읽는가 |
|---|---|
| **세션 ID** | **주소창**입니다. 세션이 생기면 `/sessions/{sessionId}` 로 바뀝니다 |
| **잡 ID** | 결과 이미지를 **우클릭 - 이미지 주소 복사**. `/v1/jobs/{jobId}/image` 형태입니다 |
| 브리프 결과 | 화면 모양으로 판별합니다 (아래 표) |
| 시안 결과 | 시안이 뜨면 성공, 거절 문구가 뜨면 거절입니다 |
| 렌더 결과 | 결과 이미지가 뜨면 `done`, 오류 문구면 `failed` 입니다 |
| **소요 (초)** | **손으로 재지 마십시오.** 실행 후 로그에서 뽑습니다 (6-9절) |

**가장 확실한 방법은 개발자 도구입니다.** `F12 - Network` 를 열고 `Preserve log` 를 켜 두면
응답 JSON 에 `sessionId`, `state`, `messageMode`, `jobId` 가 전부 들어 있습니다. 주소창과
이미지 주소로도 되지만, 브리프 결과 세 갈래를 눈으로 가르는 것보다 정확합니다.

**브리프 결과를 화면으로 가르는 법**

| 화면 | 기록할 값 | 뜻 |
|---|---|---|
| 카테고리와 타겟에 값이 차 있고 `추론` 표시가 붙음 | `brief_ready` | 정상 |
| 특정 항목을 되묻는 문구가 뜸 | `needsInput` | 판단이 서지 않아 되물음 |
| 두 값이 비어 있고 직접 채우라는 안내가 뜸 | `degraded` | 엔진이 응답하지 못함 |

셋 다 정상 동작입니다. `degraded` 는 설계된 열화이고(ADR-0005) `needsInput` 은 계약이 정한
되물음입니다. **실패로 적지 마십시오.**

### 0-9. 한 번에 한 세션씩 돕니다

**전제입니다.** `obs` 로그에는 세션 식별자가 없습니다 - `image:render` 줄만 `job=` 을 답고
`brief:fill` 과 `draft:*` 줄에는 아무 식별자도 없습니다. 여러 세션을 겹쳐 돌리면 로그 줄이
어느 회차의 것인지 가릴 수 없습니다.

한 세션을 끝내고 다음을 시작하면 로그가 시각 순서대로 쌓여 회차와 1:1로 짝지어집니다.
**회차마다 시작 시각을 적어 두면** 나중에 로그를 자를 때 기준이 됩니다.

### 0-10. 내려받은 파일 이름이 겹칩니다

다운로드 파일명이 `{제품명}.webp` 라서(`ResultView.tsx:117`) **같은 제품의 만화형과 단일
광고형이 같은 이름으로 떨어집니다.** S04 와 S14 가 둘 다 원두이므로 바로 겹칩니다.

**받는 즉시 회차 번호를 앞에 붙이십시오** - `S04_원두_만화.webp` 처럼요. 19개를 다 받은 뒤에
맞추려 하면 어느 것이 어느 회차인지 알 수 없습니다.

### 4-c. G3 발화 유도 (배포 경로, 시안까지만)

입력은 D2 에서 검증된 조합입니다. **제품을 바꾸지 않습니다** - 재현율이 이 조합의 값입니다.

제품 특징 : 무향 무알코올

### 6-9. 소요와 결과를 로그에서 뽑습니다

**되돌리기 전에 하십시오.** 로그 자체는 30일 보존이라 남지만, 실물 회차 구간을 잘라내려면
시작과 종료 시각이 필요하고 그것은 이 시트에만 있습니다.

```bash
# 회차 구간만 잘라서 집계합니다. 스텁 구간과 섞이면 지연이 조용히 낮아집니다
python3 scripts/observe.py \
  --log-dir /var/lib/docker/volumes/adgen_adgen-state/_data/logs \
  --since <실행 일자>
```

원본 줄을 직접 보려면 이렇게 합니다.

```bash
grep '^.*obs seam=' /var/lib/docker/volumes/adgen_adgen-state/_data/logs/*.log | tail -80
```

줄의 모양은 `obs seam=<이음매> outcome=<결과> elapsed_ms=<밀리초>` 이고, `image:render` 줄에만
`job=<잡ID>` 가 붙습니다. **그 잡 ID로 렌더 줄과 회차를 짝지을 수 있습니다.** 나머지 이음매는
식별자가 없으므로 시각 순서로 맞춥니다 (0-9절이 한 번에 한 세션씩 도는 이유입니다).

| 이음매 | 회차당 줄 수 | 정상 결과 |
|---|---|---|
| `brief:fill` | 1 (세션 생성) | 줄이 없으면 정상입니다. `degraded` 일 때만 남습니다 |
| `draft:generate` | 1 | `ok`. 가드레일 거절은 `refused` |
| `image:render` | 1 (`finalize` 한 회차만) | `done` |

**`refused` 와 `degraded` 를 실패로 세지 마십시오.** 전자는 가드레일이 동작한 것이고 후자는
설계된 열화입니다. `observe.py` 의 `FAILURES` 표가 이음매마다 무엇을 실패로 세는지 정해
두었고, 그 구분이 그 스크립트의 전부입니다.

**표본 수를 함께 적으십시오.** 이 스크립트는 회차가 세 건이어도 p95 를 계산합니다. 19건에서
나온 p95 는 최댓값에 가까운 값이며, 보고서에 그대로 옮기면 근거가 되지 않습니다.

**6-6 을 빼먹지 않습니다.** 전환 시점에 뜬 백업에 키가 평문으로 남습니다. 2026-08-27 에
같은 자리를 밟았고 그때도 `shred -u` 로 지웠습니다 (이슈 #291).
