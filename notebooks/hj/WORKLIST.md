## 0. 품질 티어 운용 지침

**개발과 실험은 `low`(또는 스텁), 최종 확인만 `medium`.**

이것은 새 결정이 아니라 이미 문서에 있는 것을 작업 규칙으로 옮긴 것입니다 -
[생성_파이프라인.md](../../docs/기술문서/생성_파이프라인.md) 6.2절 마지막 문단이 같은 내용입니다.

| 상황 | 티어 | 이유 |
|---|---|---|
| 배관과 합성 로직 확인 | 스텁 모드 | 요금이 나가지 않습니다 |
| 컷별 생성, 병렬, 실패 처리 개발 | `low` | 세트당 0.0974 USD. 회차를 많이 태워도 예산이 버팁니다 |
| 검증 실험 (3순위, 5순위, N18) | `low` | 판정 대상이 화풍과 일관성이라 티어가 판정 축이 아닙니다 |
| 최종 확인, 시연, 제출용 산출물 | `medium` | 세트당 0.4041 USD |

주의 세 가지입니다.

- **운영값은 그대로 만화형 `medium`입니다.** 위 규칙은 개발 중 비용 방어이지 운영 설정값을
  바꾸는 것이 아닙니다. 단일 광고형은 개발이든 운영이든 `low` 고정입니다.
- **`low`로 잰 숫자를 `medium`의 근거로 쓰지 않습니다.** 시간과 단가가 티어마다 다르고,
  병렬 시 개별 호출 팽창률도 다릅니다(`low` 44%, `medium` 64%).
- **`low` 만화형에는 관측된 결함이 있습니다** (손과 사물의 물리). 개발 중 그림이 이상한 것은
  구현 결함이 아닐 수 있으니 `medium` 1회로 먼저 갈라내고 원인을 판단합니다.

**강제 지점은 `ADGEN_IMAGE_QUALITY_OVERRIDE` 입니다** (2026-08-20 구현). 운영 티어는 계약을
타고 오고(만화형 `medium` / 단일 광고형 `low`), 개발과 실험에서 `low` 로 내리는 것은 이 엔진 쪽
환경변수로 합니다. backend 의 `COMIC_QUALITY` 상수를 고쳐서 내리면 **그 값이 그대로 배포됩니다.**
override 가 발동하면 경고 로그가 남습니다.

## A. `image:render` 실물화 마무리 (2026-08-19 배정, 최우선)

현재 [render.py](../../apps/ai-engine/src/ai_engine/render.py)의 `_render_with_model`은
**한 장을 통째로 한 번 호출**합니다. A-2(컷 경계 제어 방법) 확정과 어긋난 상태라 여기가 가장
큰 덩어리입니다.

- [ ] **A4. 05(임동규)와 인터페이스 선합의** - A1 착수 전에 먼저
  - 동시성이 두 앱에 나뉩니다(N19-a). 잡 안의 칸 5장 동시 호출은 03, 잡끼리 몰리지 않게 막는
    것은 05입니다
  - 두 앱의 허용된 결합은 `packages/contracts`의 HTTP 계약뿐입니다. 구현을 먼저 시작하면 그
    선을 넘는 쪽이 쉬워집니다
- [ ] **A1. 컷별 생성 + 3x2 합성**
  - DoD: 칸 1152 x 1152 정확, 여백 0px, 전체 3456 x 2304
  - 근거: [생성_파이프라인.md](../../docs/기술문서/생성_파이프라인.md) 6절
- [ ] **A2. 컷 병렬 호출** (2 ~ 6번 칸 동시 5건)
  - DoD: `medium` 기준 실측 139.2초 재현
  - 주의: 순차 구현이 먼저 나가면 310.8초로 `render_timeout_s`(300초)를 넘깁니다. 그 순서로
    간다면 타임아웃 상향을 함께 올려야 합니다
- [ ] **A3. 부분 실패 처리** (N20-a, 컷 부분 실패)
  - DoD: 한 칸이라도 실패하면 잡 전체 `failed`
  - 계약이 바뀌면(잡 상태에 부분 성공이 생기면) ADR을 함께 남깁니다
- [x] **A5-0. 방식 결정 (2026-08-20)** - **요청이 티어를 실어 보냅니다.** 설정을 유형별로
      쪼개지 않습니다
  - 근거는 같은 계약 안의 선례입니다. `ImageSpec` 설명이 "**호출자가 규격을 정해 보냅니다.**
    엔진이 유형을 보고 스스로 정하면 기획서 10.2의 값이 두 곳에 생기고, 한쪽만 고치는 순간
    어긋납니다"라고 못박아 뒀고, 품질 티어도 출력 유형별로 갈리는 값이라 사정이 똑같습니다
  - 실제로 backend 에 이미 그 형태가 있습니다 -
    [render.py](../../apps/backend/src/backend_core/render.py) 의 `COMIC_SPEC` /
    `SINGLE_AD_SPEC` 상수와 `spec = COMIC_SPEC if session.output_type == "comic" else ...`.
    티어는 이 줄 옆에 상수 하나가 더 붙는 모양이 됩니다
  - 소관: 미결정_대장 E-2 의 이 행이 03 소관이라 회의록 없이 정할 수 있습니다. 다만 계약을
    바꾸므로 05 와 함께 봅니다 (A4 에 얹습니다)
- [x] **A5-1. 계약 먼저 (2026-08-20 완료)** - `ImageRenderRequest` 에 `quality` 추가
  - ⚠️ **먼저 답해야 하는 것 하나**: 요청만이 티어를 정하면 0절의 "개발 중에는 `low`" 지침을
    엔진 쪽에서 누를 수단이 없어집니다. backend 가 보낸 값이 곧 티어가 되기 때문입니다
  - **잠정안대로 갔습니다.** 계약의 `quality` 는 `spec` 과 같이 **필수**이고, 엔진에는 개발용
    강제 override 를 다른 이름으로 남겼습니다 (`ADGEN_IMAGE_QUALITY` ->
    `ADGEN_IMAGE_QUALITY_OVERRIDE`). 발동하면 경고 로그를 남깁니다
  - 벤더의 `auto` 는 열거에서 뺐습니다 - 모델에게 맡기는 것이 막으려던 바로 그 상태입니다.
    `high` 는 넣되 "재지 않았다" 를 계약 설명에 적었습니다
- [x] **A5-2. 스키마 (완료)** - 양쪽 모델에 반영
  (`backend_core.models.generation`, `ai_engine.models.generation`)
- [x] **A5-3. 구현 (완료)**
  - backend: `COMIC_SPEC` 옆에 `COMIC_QUALITY = "medium"` / `SINGLE_AD_QUALITY = "low"`
  - engine: `_render_with_model` 이 설정이 아니라 요청에서 티어를 읽음
- [x] **A5-4. 문서 (완료)** - 미결정_대장 E-2 해당 행, `config.py` 의 `image_quality` docstring,
  [생성_파이프라인.md](../../docs/기술문서/생성_파이프라인.md) 6.2절 마지막 문단
  - ADR 은 만들지 않는 쪽으로 봅니다. 기존 `spec` 패턴을 1:1로 따라가는 필드 추가이고, 새로
    가르는 갈래가 없습니다. 판단이 뒤집히면 여기서 되살립니다
- [ ] **A6. 캐릭터 일관성 구현** (A-4, 캐릭터 일관성 확보 수단)
  - 1번 칸 결과를 2 ~ 6번 칸의 레퍼런스로 전달
  - 현재 대장 등급은 **잠정 진행**입니다
