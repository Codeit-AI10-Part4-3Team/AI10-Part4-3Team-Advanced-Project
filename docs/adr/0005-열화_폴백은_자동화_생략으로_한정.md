# ADR-0005: 열화 폴백은 브리프 자동 채움 생략 하나로 한정하고, 나머지 단계는 명시적으로 실패한다

- **상태**: Accepted
- **날짜**: 2026-08-09
- **결정자**: 신호정 (TL)
- **관련**: [AGENTS.md](../../AGENTS.md) 설계 제약, [API_계약.md](../기술문서/API_계약.md) 2절 및 5절,
  [생성_파이프라인.md](../기술문서/생성_파이프라인.md) 3절 및 5절,
  [용어_사전.md](../기술문서/용어_사전.md) 6절, 기획서 9.3, 12.5, 13.2

## 배경

워킹 스켈레톤은 템플릿에서 `official_fallback`을 물려받았습니다. `ai-engine`이 죽으면 `backend`가
사전 승인된 답변을 돌려주고, 그 사실을 `messageMode`에 표기합니다.
[AGENTS.md](../../AGENTS.md)는 이것을 하드 제약("열화 폴백 필수")으로 두고,
이미지 쪽 동형으로 "파인튜닝 어댑터 불가 -> base 모델 결과 + 그 사실 표기"를 적어 두었습니다.

이 프로젝트에서는 두 전제가 모두 무너집니다.

- **사전 승인된 응답이 존재할 수 없습니다.** 질의응답 도메인에서는 "지금은 답변드리기 어렵습니다"
  같은 고정 문구가 유효한 답이지만, 광고 카피는 제품마다 다릅니다. 미리 준비해 둔 카피를
  돌려주면 입력에 없는 주장을 내보내는 것이고, 이는 근거 기반 생성 원칙과 표시광고법 양쪽에
  걸립니다 (기획서 5.5).
- **어댑터와 base의 이분법이 없습니다.** 기준 구성은 전 구간 GPT API이고 파인튜닝은 보류입니다
  (기획서 13.2, ADR-0004 예약). 열화할 대상 자체가 없습니다.

한편 기획서에는 폴백 개념이 아예 없고 오류 표시만 있습니다 (12.5). 이 상태를 그대로 두면
**가드레일이 생성물을 거절했을 때의 동작이 정해지지 않습니다.** 그래서 차단 등급이었습니다
([미결정_대장.md](../기술문서/미결정_대장.md) N1).

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. **자동화 생략형으로 재정의** | 실제로 동작 가능한 열화가 하나 남습니다. 스켈레톤이 검증하던 성질(열화가 응답에 드러남)을 유지합니다 | 열화의 정의가 템플릿과 달라져 `AGENTS.md`를 함께 고쳐야 합니다 |
| B. 잠정안 유지 (텍스트 단계 폴백 / 이미지 단계 실패) | 문서를 고칠 필요가 없습니다 | `draft:generate`의 폴백 응답으로 무엇을 돌려줄지 정의할 수 없습니다. 지어내면 원칙 위반입니다 |
| C. 폴백 전면 폐지 | 규칙이 가장 단순합니다 | `messageMode`가 사라지고, 열화 경로가 응답에 드러나야 한다는 성질도 함께 사라집니다 |

## 결정

**A를 택합니다.** 열화는 "미리 준비한 답으로 바꿔치기"가 아니라 **"자동화 단계를 건너뛰고
사용자 입력으로 진행"**을 뜻합니다.

| 단계 | 의존이 실패하면 | 응답 |
|---|---|---|
| `brief:fill` | **자동 채움을 생략**하고 사용자가 직접 채우게 합니다 | 201, `state: brief_filling`, `needsInput`, 해당 필드 `filledBy: "user"` |
| `draft:generate` | 폴백 없음 | 503 `UPSTREAM_UNAVAILABLE` |
| `draft:patch` | 폴백 없음. 시안 원문은 그대로 둡니다 | 503 `UPSTREAM_UNAVAILABLE` |
| `image:render` | 폴백 없음 | 잡 `status: failed` + `error.code` |

`messageMode`는 남기되 값을 바꿉니다.

| 값 | 뜻 |
|---|---|
| `normal` | 모든 자동화 단계가 정상 동작했습니다 |
| `degraded` | 자동 채움을 건너뛰었습니다. 화면이 이 사실을 구분해 표시합니다 |

`official_fallback`은 **폐기**합니다. 템플릿 잔재이며, 이 도메인에는 대응하는 동작이 없습니다.

가드레일이 생성물을 거절했을 때(`unsupported_claim`)도 폴백하지 않습니다. **같은 부분을 1회
재생성하고, 재차 위반하면** `CONTENT_POLICY_REJECTED`로 사용자에게 돌려줍니다. 위반한 문구를
서버가 임의로 다듬어 내보내는 경로는 두지 않습니다 -- 다듬은 결과가 근거 안에 있는지를 다시
아무도 검사하지 않기 때문입니다.

B를 택하지 않은 이유는 **폴백 응답의 내용을 정의할 수 없기 때문**입니다. "폴백한다"고 적어 두고
무엇을 돌려줄지는 구현자에게 남기면, 구현자는 결국 모델 없이 카피를 지어내는 코드를 씁니다.

C를 택하지 않은 이유는 **잃는 것이 있기 때문**입니다. `brief:fill` 실패는 실제로 우회 가능한
상황입니다. 사용자가 카테고리와 타겟을 직접 고르면 파이프라인은 그대로 진행됩니다. 이것을 오류로
끊으면 살릴 수 있는 세션을 버립니다.

## 결과

**생기는 제약**

- `AGENTS.md`의 "열화 폴백 필수" 항목이 이 ADR을 가리키도록 바뀝니다. 사전 승인 응답 표현과
  어댑터 예시는 이 프로젝트에 해당하지 않습니다.
- `brief:fill` 실패 경로는 **테스트 대상**입니다. `ai-engine`을 끈 상태에서
  `POST /v1/sessions`가 201과 `messageMode: degraded`를 돌려주어야 합니다. 이것이 스켈레톤의
  열화 검증을 대체합니다.
- 프론트엔드는 `degraded` 세션을 일반 세션과 구분해 표시합니다. 표기를 지우면 사용자는 자동
  추론이 동작한 줄 압니다 ([역할_가이드/06-프론트엔드.md](../역할_가이드/06-프론트엔드.md)).
- 가드레일 재생성은 **1회**입니다. 횟수를 열어 두면 거절이 반복될 때 비용이 무한히 늡니다.

**쉬워지는 것**

- 실패 응답의 종류가 줄어듭니다. `brief:fill` 하나만 열화이고 나머지는 전부 오류입니다.
- 지표가 오염되지 않습니다. 폴백으로 만들어진 카피가 생성 결과에 섞이면 환각 억제율이
  실제보다 좋게 나옵니다.

**어려워지는 것**

- `brief:fill`이 자주 실패하면 사용자가 카테고리와 타겟을 매번 직접 고르게 됩니다. 이 경우
  자동 추론의 가치가 실측으로 드러나므로, `degraded` 비율을 로그에 남깁니다.

**재검토 신호**

- 파인튜닝을 되살리기로 할 때 (ADR-0004). 그때는 어댑터 -> base 열화가 실재하므로 표가 늘어납니다.
- `CONTENT_POLICY_REJECTED` 비율이 높게 나올 때. 재생성 1회 제한이 과한지 다시 봅니다.
