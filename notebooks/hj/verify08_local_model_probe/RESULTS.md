# 검증 8순위 실측 결과 (2026-08-15)

수행: 신호정(03). 이 문서는 **실험 기록이지 결정이 아닙니다.** A-5(로컬 모델 채택 여부)의
확정 근거는 검증 4순위 결과와 회의록입니다.

## 1. 8순위 완료 조건: 로컬 모델은 이 VM 에서 구동됩니다

두 후보 모두 가용 VRAM 22.5GB 안에서 돌았습니다. 8순위의 완료 조건인 "로컬 모델 구동 가능
여부 확정"은 **가능**으로 닫힙니다.

| | FLUX.1-schnell Q8_0 | SDXL base 1.0 fp16 |
|---|---|---|
| peak VRAM | **15.75GB** (reserved 16.21GB) | **11.79GB** |
| 장당 생성 시간 (1088 x 1088) | **9.9 ~ 11.1초** | 13.6 ~ 14.9초 |
| 모델 로드 (프로세스당 1회) | 인코더 56.6초 + 트랜스포머 175.7초 | 약 60초 |
| 디스크 | 약 22.7GB | 약 10GB (IP-Adapter 포함) |
| 라이선스 | Apache-2.0 | CreativeML Open RAIL++-M |

세 번째 후보인 **Qwen-Image 도 이 VM 에서 돌았습니다**(peak 18.4GB). 한글을 직접 그리는
유일한 후보이지만 장당 215초라 별도로 다룹니다 - [PIPELINE_SURVEY.md](PIPELINE_SURVEY.md) 3절.

**FLUX 는 두 단계로 나눠야 들어갑니다.** 텍스트 인코더(9.86GB)와 트랜스포머(15.75GB)를 동시에
올리면 22.5GB 를 넘고, diffusers 의 CPU 오프로드로 우회하면 호스트 RAM 16GB 가 먼저 터집니다.
그래서 `flux_probe.py` 는 인코딩을 먼저 끝내고 인코더를 해제한 뒤 트랜스포머를 올립니다.
해제 후 가용이 23.36GB 로 돌아오는 것을 로그로 확인했습니다.

주의: 이 분리를 할 때 `torch.inference_mode()` 를 빠뜨리면 임베딩이 계산 그래프로 인코더
가중치를 붙들어 2단계에서 OOM 이 납니다(실제로 한 번 겪었습니다).

### 1.1 fp8 이 아니라 Q8_0 인 이유

계획은 fp8(e4m3) 이었으나 diffusers 에서 literal fp8 을 쓰려면 **bf16 원본 23.8GB 를 받아 로드
시점에 양자화**하는 경로뿐입니다. fp8 로 저장된 체크포인트를 그대로 읽으면 bf16 으로 업캐스트되어
22.5GB 를 넘깁니다. 디스크 예산이 이를 허용하지 않아 같은 8비트 계층인 GGUF Q8_0(12.7GB)을
썼습니다. 대가는 Ada 의 네이티브 fp8 가속을 못 쓰는 것이며, 속도가 판단의 갈림돌이 되면 그때
다시 볼 항목입니다.

기준선은 [verify01 의 `single` 회차](../verify01_korean_text_rendering/) 10회입니다.

| | gpt-image-2 | FLUX.1-schnell | SDXL |
|---|---|---|---|
| 장당 소요 | 18.1 ~ 28.2초 (평균 20.3) | **9.9 ~ 11.1초** | 13.6 ~ 14.9초 |
| 장당 단가 | $0.0069 (고정) | $0 (한계비용) | $0 (한계비용) |
| 한국어 카피 렌더 | **정확** | 불가 | 불가 |
| 한국어 프롬프트 이해 | 정상 | **실패** | 미측정 |
| negative prompt | 해당 없음 | **무효** | 유효 |
| IP-Adapter | 불가 | 사실상 불가 (3.4절) | **동작** |

## 3. 발견

### 3.1 FLUX 는 한국어 프롬프트를 이해하지 못합니다

`conditions.py` 의 `prompt_single_ad()` 를 **원문 그대로** 넣었더니 제품도 화풍도 카피도 없는,
주제와 무관한 발코니 사진이 나왔습니다(`single_ko_verbatim.png`). 텍스트 인코더가 T5-XXL 이라
한국어 이해도가 낮습니다.

**로컬 모델을 채택하면 프롬프트 조립 단계에 한국어에서 영어로의 번역이 들어갑니다.** 지금
파이프라인 설계에 없는 단계이고, 번역 품질이 곧 이미지 품질이 됩니다. 이 문서의 모든 로컬
모델 결과는 영어 프롬프트로 얻은 것입니다.

### 3.2 어느 조합도 글자 없는 제품컷을 만들지 못합니다

두 모델 모두 한글을 그리지 못하는 것은 같습니다. 다른 것은 **무엇을 어기는가**입니다.
2 장면 x 시드 5개(42 ~ 46)로 돌린 결과입니다.

| | 제품 정확 | **글자 없음** | 톤 일관성 |
|---|---|---|---|
| FLUX.1-schnell | **10/10** | **0/10** | 낮음 (시드마다 팔레트가 바뀜) |
| SDXL, IP-Adapter 없음 | 6/10 | 3/10 | 낮음 |
| SDXL + IP-Adapter | **10/10** | **0/10** | **높음** |

판정은 03 의 육안이며 **판정자 확인이 필요합니다.** 이미지는
`outputs/로컬모델_탐색/FLUX_장면2종_시드5/` 와 `SDXL_IP어댑터_온오프_시드5/` 에 있습니다.

- **FLUX 가 글자를 못 뺍니다.** "Do not write any text, letters or numbers anywhere" 를
  명시했는데도 10장 전부 가짜 글리프를 그렸습니다. schnell 은 guidance distilled 라 negative
  prompt 가 무효이고, 부정 지시를 강제할 수단이 프롬프트에 없습니다.
- **SDXL 도 사실상 못 뺍니다.** negative prompt 가 동작하는데도 10장 중 7장에 글자가 있습니다.
  이유는 단순합니다 - **제품 패키지에는 원래 라벨이 있습니다.** 모델은 패키지를 그리면서 라벨
  자리에 글자 비슷한 것을 채웁니다.
- **SDXL 은 무엇을 그릴지도 자주 놓칩니다.** 제품이 어긋난 4장에는 인물 얼굴, 통 모양 용기,
  화분이 섞여 있습니다. 프롬프트의 "product-only shot" 과 negative 의 `people` 을 동시에
  어긴 장도 있습니다.

> **표본 2장으로 냈던 초판 결론을 정정합니다.** 초판은 "SDXL 은 글자를 지킨다(2/2)"였는데,
> 그 2장이 **제품을 그리지 못한 장**이었습니다. 패키지가 없으니 라벨도 없었던 것이고, 글자
> 억제 능력으로 읽은 것이 오독이었습니다. 5장으로 늘리자 3/10 으로 떨어졌습니다.

**로컬 모델을 쓰면 카피는 후처리 합성이 전제인데(3.1), 그 합성의 입력은 글자가 없는 깨끗한
제품컷이어야 합니다. 지금 어느 조합도 그것을 만들지 못합니다.** gpt-image-2 는 예비안 10회에서
100% 로 글자를 넣지 않았습니다(verify01 RESULTS 2.2절). 이것이 로컬 경로의 실제 진입 장벽이며,
후속 조사는 [PIPELINE_SURVEY.md](PIPELINE_SURVEY.md) 에 있습니다.

### 3.3 IP-Adapter 는 실제로 동작하며 델타가 큽니다 (SDXL)

레퍼런스로 gpt-image-2 결과 1장(`단일광고형_기준선/single-01.png`)을 주고 같은 프롬프트를 on/off 로 돌렸습니다.
scale 0.6.

- **off**: 제품 정확 6/10. 인물 얼굴, 통 모양 용기, 화분이 섞였습니다.
- **on**: 제품 정확 **10/10**. 두 장면 모두 물티슈 파우치로 교정되었고, 레퍼런스의 연녹색
  팔레트와 제품 렌더 질감, 상단 카피 자리까지 옮겨왔습니다. **시드가 달라도 톤이 유지됩니다** -
  off 에서는 시드마다 배경과 색이 흩어졌습니다.

즉 IP-Adapter 는 브랜드 톤 이전만 하는 것이 아니라 **SDXL 의 프롬프트 충실도 문제까지 함께
가려 줍니다.** 레퍼런스가 "무엇을 그릴지"를 텍스트보다 강하게 지시하기 때문입니다. 이것은 외부
API 경로에는 없는 통제 수단입니다(ADR-0003 이 "어려워지는 것"으로 적어 둔 항목).

**브랜드 톤 일관성이라는 목적에 대해서는 이번 탐색에서 가장 좋은 결과입니다.** 검증 3순위가
묻는 성질과 같은 축이며, 프롬프트만으로는 얻지 못한 것을 얻었습니다.

부작용도 확인했습니다. **레퍼런스에 글자가 있으면 그 글자까지 옮겨옵니다** (10/10). negative
prompt 로 억제되지 않습니다. 이 부작용을 겨냥한 후속 실험이
[PIPELINE_SURVEY.md](PIPELINE_SURVEY.md) 4.1절(InstantStyle)입니다.

### 3.4 FLUX 파인튜닝은 VRAM 이 아니라 디스크가 먼저 막습니다

- GGUF 양자화본은 학습 대상이 아닙니다. FLUX LoRA 학습에는 bf16 또는 bnb NF4 base 가 필요하고,
  그러려면 **bf16 원본 23.8GB** 를 받아야 합니다. 현재 VM 여유는 16GB 입니다.
- 즉 지금 상태에서 FLUX 파인튜닝은 **시작할 수 없습니다.** 무언가를 지우고 받아야 하며,
  그 판단은 04 와 05 가 함께 해야 합니다.
- schnell 은 timestep distilled 라 LoRA 를 얹으면 distillation 이 깨지기 쉽다는 것이 알려져
  있고, 그래서 `ostris/FLUX.1-schnell-training-adapter` 같은 보조 어댑터가 따로 존재합니다
  (`추정`, 실측하지 않았습니다).

### 3.5 SDXL LoRA 학습은 여유 있게 들어갑니다

측정만 했고 산출물은 만들지 않았습니다(ADR-0004 파인튜닝 보류).

| 항목 | 값 |
|---|---|
| 조건 | 1024px, batch 1, rank 16, gradient checkpointing, AdamW |
| 학습 대상 파라미터 | 23.22M |
| **peak VRAM** | **11.54GB** / 23.66GB |
| 스텝 소요 | 1.29초 (2회차 기준) |

`training/configs/brand-lora.example.yaml` 의 기본값(rank 16, target_modules)을 그대로 쓴
결과입니다. 1000 스텝이면 약 22분이며, **하드웨어가 SDXL LoRA 를 막지 않습니다.**

### 3.6 비용은 판단 축에서 빠집니다

단일 광고형의 gpt-image-2 단가는 **$0.0069** 입니다. 만화형($0.1171)과 달리 1만 장을 뽑아도
$69 이고, 결제 계정은 학원 소유라 우리가 관리할 수 있는 항목도 아닙니다
([ADR-0011](../../../docs/adr/0011-배포_환경_스펙과_권한_경계.md)).

따라서 ADR-0003 의 재검토 신호 중 "세션당 단가가 감당할 수 없는 숫자로 나올 때"는 **발동하지
않을 가능성이 높습니다** (`높은 신뢰`). 비용을 로컬 채택의 근거로 쓰지 마십시오.

## 4. 4순위에 넘기는 것

**넘기는 것**

1. 이 문서와 [PIPELINE_SURVEY.md](PIPELINE_SURVEY.md) 의 실측표.
2. 재현 스크립트 - `flux_probe.py`, `sdxl_probe.py`, `pipeline_smoke.py`, `qwen_probe.py`,
   `compose_copy.py`, `lora_memprobe.py`. 조건은 `prompts_*.json` 에 고정돼 있습니다.
3. 고정된 생성 조건(1088 x 1088, seed 42 ~ 46, FLUX 4 steps / SDXL 30 steps CFG 7.0 /
   Qwen 30 steps true CFG 4.0).
4. 결과 이미지와 대조 시트 - `outputs/로컬모델_탐색/`.
5. 라이선스 확인 결과(6절).

**넘기지 않는 것**

- 채택 권고와 우열 판정. 4순위의 수행자는 04 이고 판정자는 임동규, 송기하 2명입니다.
- 이 문서의 이미지를 4순위 비교 결과물로 제출하는 것. 조건이 같으면 수행자가 03 이 되어
  기획서 15절의 자기 채점 금지에 걸립니다.

**4순위의 물음이 바뀔 수 있습니다.** 비용 축이 죽고(3.6) 한국어 텍스트는 GPT 가 확실히
앞서므로(3.1, 3.2), 남는 물음은 이렇게 좁혀집니다.

> IP-Adapter 로 얻는 브랜드 톤 통제가, 한국어 카피를 후처리 합성으로 옮기는 비용을 감당할
> 만한가.

판정자 두 분이 볼 물음이 "어느 이미지가 예쁜가"가 아니라 이것이 되도록 04 와 조율이 필요합니다.

## 5. 후보 순위에 대한 소견 (가설, 결정 아님)

탐색 착수 시점의 1순위는 FLUX 였고 라이선스(Apache-2.0)만 보면 지금도 그렇습니다. 다만
**실측은 SDXL 쪽을 가리킵니다.**

| 축 | 우세 | 크기 |
|---|---|---|
| 생성 속도 | FLUX | 10.5초 vs 14.3초 |
| **프롬프트 충실도 (단독 사용 시)** | **FLUX** | 2/2 vs 0/2 (3.2) |
| 라이선스 | FLUX (Apache-2.0) | 재배포하지 않으므로 둘 다 성립 |
| **텍스트 억제** | **SDXL** | 후처리 합성 경로의 선행 조건 (3.2) |
| **IP-Adapter** | **SDXL** | 4순위 완료 조건에 명시된 항목. 충실도 문제까지 덮음 (3.3) |
| **파인튜닝 실행 가능성** | **SDXL** | FLUX 는 디스크가 막음 (3.4, 3.5) |

**단독 성능만 보면 FLUX 가 낫고, 통제 수단까지 넣으면 SDXL 이 낫습니다.** FLUX 의 우위인
충실도는 SDXL + IP-Adapter 조합이 상쇄하는 반면, SDXL 의 우위인 어댑터 생태계와 학습 경로는
FLUX 쪽에 대응물이 없습니다.

**이 문서만으로는 로컬 경로가 성립하지 않습니다.** 3.2 절이 보여 주듯 base 모델을 무엇으로 고르든
글자 없는 제품컷이 나오지 않기 때문입니다. 그 구멍을 메우는 방법과, 한글을 직접 그리는 후보
(Qwen-Image)를 실제로 재 본 결과는 **[PIPELINE_SURVEY.md](PIPELINE_SURVEY.md)** 에 있습니다.
후보 순위의 결론은 그쪽 6절을 보십시오.

`추정`입니다. 표본이 조건당 5장이고 판정자 확인이 필요합니다(7절).

## 6. 라이선스 확인 결과

| 모델 | 라이선스 | 상업 이용 | 파인튜닝 | 비고 |
|---|---|---|---|---|
| FLUX.1-schnell | Apache-2.0 | 가능 | 가능 | 공식 저장소가 게이팅(익명 401)이라 토큰 필요 |
| FLUX.1-dev | 비상업 | **불가** | - | 생태계 어댑터 다수가 dev 기준. 쓰지 마십시오 |

**가중치를 재배포하지 않으므로 둘 다 성립합니다** (`높은 신뢰`). 채택이 결정되면 ADR 에 원문
근거를 달아야 합니다(AGENTS.md 가 base 모델 선택에 ADR 을 지정).

주의: 이번 다운로드는 공식 저장소가 게이팅되어 **비게이팅 미러**(`unsloth/FLUX.1-schnell`,
`city96/FLUX.1-schnell-gguf`, 둘 다 Apache-2.0)를 썼습니다. ADR 의 라이선스 근거는 공식
저장소 원문으로 달아야 합니다.

## 7. 확인하지 않은 것

- SDXL 의 한국어 프롬프트 이해도. 영어로만 측정했습니다.
- IP-Adapter scale 값의 영향. 0.6 한 값만 봤습니다.
- FLUX 용 IP-Adapter(XLabs 계열). schnell 지원이 불확실해 시도하지 않았습니다.
