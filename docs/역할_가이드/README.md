# 역할 가이드

**누가 무엇을 하는지**를 역할별로 정리하는 곳입니다. 언제 하는지는
[역할_일정/](../역할_일정/README.md)에 따로 있습니다 — 두 축을 한 문서에 섞으면 일정이 바뀔 때마다
역할 정의까지 흔들립니다.

## 규칙

- 파일명은 `NN-역할명.md` (한글). `역할_일정/`과 **같은 번호**를 씁니다 — 1:1 대응입니다.
- 역할을 추가하면 **두 폴더에 모두** 파일을 만드세요. 한쪽만 있으면 담당은 있는데 일정이 없거나
  그 반대가 됩니다.
- `CODEOWNERS`의 경로 소유자와 여기 역할이 일치해야 합니다. 어긋나면 리뷰 자동 배정이 실제
  담당자에게 가지 않습니다.

되어 그 사람의 PR이 영구히 막히므로, 해당 줄은 TL로 대체하고 이유를 파일에 적어 두었습니다.

## 5명이 7역할을 맡는 방법

역할은 **일의 묶음**이고 사람은 5명이므로 겸임이 발생합니다. 겸임 자체는 정상이지만
아무 조합이나 되는 것은 아닙니다.

### 금지 조합 (이유가 있는 제약)

| 조합 | 왜 안 되나 |
|---|---|
| **04 학습 + 07 QA** | 자기가 학습시킨 모델을 자기가 채점하게 됩니다. 자기채점 편향은 이 프로젝트의 지표 전체를 무효로 만듭니다 |
| **03 생성 + 07 QA** | 위와 같은 이유 — 가드레일 on/off 델타를 만든 사람이 그 델타를 검증하게 됩니다 |
| **02 테크리드 + 07 QA** | `.github/`(품질 게이트)와 `e2e/`의 오너가 같아지면, 게이트를 느슨하게 만드는 변경을 아무도 막지 않습니다 |

### 권장 조합 예시

착수 회의에서 팀 상황에 맞게 고르되, 위 금지 조합만은 피하세요.

| 안 | 사람1 | 사람2 | 사람3 | 사람4 | 사람5 |
|---|---|---|---|---|---|
| A (AI 비중 높음) | 01 PM + 07 QA | 02 테크리드 + 05 백엔드/인프라 | 03 AI 생성 | 04 AI 학습 | 06 프론트 |
| B (배포 비중 높음) | 01 PM + 06 프론트 | 02 테크리드 | 03 AI 생성 + 07 QA\* | 04 AI 학습 | 05 백엔드/인프라 |
| C (프론트 분리) | 01 PM | 02 테크리드 + 03 AI 생성 | 04 AI 학습 + 05 인프라 | 06 프론트 | 07 QA |

\* 안 B의 `03 + 07`은 금지 조합입니다. 부득이 택한다면 `apps/ai-engine/eval/`의 채점 기준
변경에 **01 PM의 승인**이 반드시 걸리도록 `CODEOWNERS`를 구성하세요.

      (PR 작성자 본인의 승인은 카운트되지 않아, 단독 오너 경로는 그 사람의 PR이 영구 블록됩니다)
- [ ] 배정된 GitHub ID가 **실제 존재하고 이 저장소에 write 권한**이 있는가
