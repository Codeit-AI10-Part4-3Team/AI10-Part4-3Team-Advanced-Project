# 문서 작성 규약

제출물 문서를 **어떤 문체와 어떤 문자로 쓰는가**에 대한 규약입니다. 무엇을 어디에 쓰는가(폴더
배치, 한글/영어 명명)의 정본은 [AGENTS.md](../../AGENTS.md) 명명 규약이며 여기에 복제하지 않습니다.

| 목적 | 문서 |
|---|---|
| 폴더 배치, 한글/영어 명명, mermaid | [AGENTS.md](../../AGENTS.md) 명명 규약 |
| **문체와 문자** | 이 문서 |
| 리뷰 코멘트 작성법 | [코드_리뷰_가이드.md](코드_리뷰_가이드.md) |
| 팀 메신저에 보낼 텍스트 | [메신저_규약.md](메신저_규약.md) |

이 문서 자신도 아래 규칙을 지켜 쓰여 있습니다. 규칙을 어긴 문서가 규칙을 설명하면 아무도 믿지
않기 때문입니다.

## 1. 적용 범위

**사람이 공유하여 읽을 문서**에 적용합니다. 문체(2절)와 문자(3절)는 적용 범위가 다르므로
따로 표기합니다.

| 문서 | 문체 | 문자 | 왜 |
|---|---|---|---|
| `docs/기획서/` `docs/기술문서/` | 예 | 예 | 심사 제출물의 본체이고 PDF로 변환됩니다 |
| `docs/adr/` | 예 | 예 | 결정의 근거로 외부에 인용됩니다 |
| **`docs/회의록/`** | 예 | 예 | **같은 이유입니다.** 미결정 항목을 닫는 유일한 근거이고(기획서 14.3), ADR과 기술문서가 링크로 인용합니다 |
| **`docs/보고서/`** | 예 | 예 | 위의 "제출 보고서" 행이 가리키는 실체입니다. 실측값의 정본이라 ADR이 인용합니다 |
| 제출 보고서, 발표 자료의 텍스트 | 예 | 예 | PDF로 변환됩니다 |
| PR 리뷰 코멘트 | 예 | 예 | 공개 저장소이고 심사 대상 이력에 남습니다 |
| `docs/공통_가이드/` `docs/pr-checklist.md` | 예 | 예 | 팀원 전원이 가장 자주 읽는 문서입니다 |
| **`docs/역할_일정/`** | 예 | **아니오** | 팀 내부 진행 추적입니다. PDF로 변환하지 않고, 경고 아이콘이 지연과 차단의 앵커로 실제로 쓰입니다 |
| `README`, 이슈 본문, 협업 일지 | 예 | 아니오 | 사람이 읽지만 훑어 읽습니다. 아이콘이 스캔 속도를 높입니다 |
| `AGENTS.md` `CLAUDE.md` | 아니오 | 아니오 | 에이전트 컨텍스트로 소비되고, 경고 아이콘이 위험 항목의 앵커입니다 |
| 코드 주석 | 아니오 | 아니오 | 영어로 씁니다 ([CLAUDE.md](../../CLAUDE.md) 응답 계약) |
| `docs/역할_가이드/` | 예 | 아니오 | 역할 정의이고 제출물이 아닙니다. `docs/역할_일정/`과 같은 판단입니다 |

**표에 `docs/` 하위 8개 폴더가 모두 있습니다.** 빠진 행이 있으면 그 폴더는 규칙이 없는 것이
아니라 **판정할 수 없는 상태**가 됩니다 -- 스크립트로 재면 위반이 나오는데 위반인지 아닌지를
아무도 말할 수 없습니다. 그 상태로 두면 리뷰에서 지적이 갈립니다 (PR #134 리뷰에서 실제로
`docs/회의록/` `docs/역할_일정/` `docs/보고서/` 세 폴더가 비어 있는 것이 발견되었습니다).

문자 규칙이 갈리는 기준은 **독자가 아니라 용도**입니다. PDF 변환을 거치는 문서는 폰트에 없는
문자가 네모로 깨지거나 조용히 사라지므로 손해가 실재합니다. 반대로 GitHub 웹과 에이전트
컨텍스트에서만 소비되는 문서는 아이콘이 위험 항목의 시각적 앵커로 기능해, 훑어 읽는 속도를
실제로 높입니다.

**근거 등급과 문자 규칙은 다른 축입니다.** `docs/역할_일정/`은
[AGENTS.md](../../AGENTS.md) 근거 자료 규칙에서 근거이면서 문자 규칙은 "아니오"입니다. 어긋난
것이 아닙니다 -- 근거 등급은 "그대로 따르는가"를 정하고, 문자 규칙은 "PDF로 변환되는가"를
정하기 때문입니다. 같은 문서가 팀에게 구속력이 있으면서 심사 제출물이 아닐 수 있습니다.

`AGENTS.md`와 `CLAUDE.md`도 사람이 읽습니다. 그럼에도 제외하는 이유는 독자가 없어서가 아니라
위의 용도 기준 때문입니다.

### 1-a. 기존 문서는 어떻게 하나

**오늘 이후 새로 쓰는 글부터 적용합니다.** 기존 문서는 다른 이유로 손댈 때 그 부분만 함께
고칩니다. 규칙을 맞추는 것만이 목적인 일괄 치환 PR을 내지 마세요.

`docs/공통_가이드/`와 `docs/pr-checklist.md`는 이 규약보다 먼저 쓰였고, 5절의 스크립트로 재면
위반이 약 500건입니다(가운뎃점 160, em dash 106, 화살표 84, 경고 기호 38 등). 일괄 치환은
diff가 커서 리뷰가 불가능하고, 무엇보다 규약이 시행되기도 전에 지적 500건을 만들어 냅니다.
지킬 수 있는 크기로 시작해야 규약이 살아남습니다.

**2026-08-19에 표에 행 넷을 더하면서 물려받은 빚을 함께 적어 둡니다.** 숨기면 다음 사람이
"위반 0건인 저장소"라고 오해하고, 적어 두면 그것이 얼마나 남았는지 세는 기준이 됩니다.

| 폴더 | 새 등급 | 물려받은 위반 |
|---|---|---|
| `docs/보고서/` | 문자 예 | **0건.** 이미 지키고 있었습니다 |
| `docs/회의록/` | 문자 예 | **35건** (가운뎃점 16, em dash 9, 곱셈 기호 4, 화살표 3 등) |
| `docs/역할_일정/` | 문자 아니오 | 82건이 있으나 **위반이 아닙니다** |
| `docs/역할_가이드/` | 문자 아니오 | 113건이 있으나 **위반이 아닙니다** |

**실제로 갚아야 하는 것은 `docs/회의록/` 35건뿐이고, 그것도 1-a에 따라 지금 갚지 않습니다.**
회의록을 문자 규칙 대상으로 올린 것은 그것이 미결정 항목을 닫는 유일한 근거이기 때문입니다.
`docs/역할_일정/`과 `docs/역할_가이드/`를 "아니오"로 둔 것이 195건의 즉시 위반을 만들지 않는
쪽이기도 하지만, **그것이 이유는 아닙니다** -- 이유는 두 폴더가 PDF로 변환되지 않는다는 것이고,
건수는 그 판단이 옳았는지의 방증입니다.

## 2. 문체: 경어체

읽는 대상에 심사자가 포함되므로 `~입니다` / `~습니다`로 씁니다.

- 표 안의 문장도 같습니다. 명사로 끝나는 셀은 그대로 둡니다.
- **내포절은 원형을 유지합니다.** 경어체는 문장 최종 어미에만 적용합니다.
  - 맞음: 모든 데이터를 백엔드가 소유한다는 것입니다.
  - 틀림: 모든 데이터를 백엔드가 소유합니다는 것입니다.
- **다이어그램 라벨은 명사구입니다.** mermaid 노드, 축 제목, 범례에는 경어체를 적용하지 않습니다.
- 영문 문서는 전환이 필요 없습니다. 평서형 산문이 이미 중립적인 전문 문체입니다.

## 3. 문자: 키보드로 칠 수 있는 것만

한글, 숫자, 라틴 문자, ASCII 문장부호만 씁니다.

이유는 세 가지입니다. 폰트와 PDF 변환기가 나머지를 치환하거나 누락합니다. 뷰어마다 다르게
렌더링합니다. 그리고 인용하거나 검색하려는 독자가 자기 키보드에 없는 문자를 다시 칠 수 없습니다.

| 쓰지 않을 것 | 대신 쓸 것 |
|---|---|
| 가운뎃점 | 쉼표, 또는 복합어에는 슬래시 |
| em dash, en dash | 하이픈, 콜론, 또는 문장을 나눕니다 |
| 화살표 기호 | `->`, 또는 연결어(따라서, 그래서) |
| 경고 기호, 정보 기호, 체크 이모지 | "주의:", "참고:", 또는 문장으로 |
| 곱셈 기호 | 소문자 x |
| 말줄임표 문자 | 마침표 세 개 |
| 둥근 따옴표, 둥근 아포스트로피 | 곧은 따옴표 |
| 체크 표시, 가위표 | O 와 X, 또는 예 와 아니오 |
| 로마 숫자 글리프, 원문자 숫자 | 1, 2, 3 또는 (1), (2) |
| 섹션 기호 | `2절`, `4-a절` |

### 3-a. 물결표는 양쪽을 띄웁니다

물결표는 키보드로 칠 수 있으므로 범위 표기에 쓸 수 있습니다. 다만 **반드시 띄어 씁니다**:
`1 ~ 2`, `08-04 ~ 08-31`.

붙여 쓰면 GFM이 다음 물결표와 짝을 지어 그 사이를 취소선으로 렌더링합니다. `1~2 3~4`는
"2 3"이 지워진 채로 보입니다. 산문 안의 다른 물결표도 같습니다. 띄우거나 `\~`로 이스케이프합니다.

### 3-b. 예외

코드, 경로, 명령, 식별자, 파일명은 원문 그대로 둡니다. 백틱으로 감싸고 안쪽은 바꾸지 않습니다.
실행 가능성이 조판보다 우선합니다.

    맞음: `--max-instances=1`
    틀림: `—max-instances=1`

인용문도 같습니다. 제목, 인용, 소프트웨어가 화면에 실제로 출력하는 문자열을 고쳐 쓰면 시스템의
동작을 잘못 보고하게 됩니다.

## 4. 그 밖의 서식

- 다이어그램은 mermaid 코드 블록으로 씁니다. 이미지는 diff에 변경이 보이지 않습니다.
  디렉토리 트리는 일반 코드 블록을 유지합니다.
- **규칙에는 이유를 함께 적습니다.** 이유 없는 규칙은 사람도 에이전트도 무시합니다.
- 불확실한 기술 주장에는 신뢰도를 표기합니다. 라벨과 기준은
  [코드_리뷰_가이드.md](코드_리뷰_가이드.md) 4절이 정본입니다.
- **근거 문서는 이름으로 인용하고, 행 번호를 쓰면 확인 시점을 함께 적습니다.** 절 제목이나
  항목 ID(`미결정_대장 B-11`, `구현_범위 4.2절`)는 문서가 자라도 그대로지만 행 번호는 쓰는
  순간부터 밀립니다 -- 회의록이 대장의 행 번호를 가리킨 자리가 세 번 어긋났고, 그때마다
  읽는 사람이 엉뚱한 줄을 근거로 읽었습니다. 이름으로 가리킬 수 없어 행 번호가 필요하면
  `(2026-08-28 확인 기준)` 처럼 확인한 날을 붙여, 읽는 사람이 다시 세어야 하는지를 판단할
  수 있게 합니다.

## 5. 제출 전 점검

코드 블록 밖의 비ASCII 문장부호를 훑습니다. PDF로 변환하기 **전에** 원본 마크다운에 돌립니다.

```python
import re, sys, unicodedata

src = open(sys.argv[1], encoding="utf-8").read()
body = re.sub(r"```.*?```", "", src, flags=re.S)   # 펜스 코드 블록 제외
body = re.sub(r"`[^`]*`", "", body)                 # 인라인 코드 제외

for line_no, line in enumerate(body.splitlines(), 1):
    for ch in line:
        if ord(ch) < 128 or "HANGUL" in unicodedata.name(ch, ""):
            continue
        print(f"{line_no}: {ch!r} {unicodedata.name(ch, 'unnamed')}")
```

다이어그램 소스는 펜스 블록 안에 있으므로 이 검사가 건너뜁니다. mermaid 노드 라벨은 보고서에
**보이는 텍스트로 렌더링되므로** 같은 규칙을 따르며, 따로 확인해야 합니다.
