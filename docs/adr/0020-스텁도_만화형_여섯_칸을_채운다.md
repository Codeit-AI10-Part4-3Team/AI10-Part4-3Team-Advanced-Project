# ADR-0020: 스텁도 만화형 여섯 칸을 채웁니다

- **상태**: Accepted
- **날짜**: 2026-08-27
- **결정자**: 신호정 (소관 03, AI 생성과 서빙)
- **근거**: [2026-08-27 회의록](../회의록/2026-08-27_안건_12건_확정.md) 02번 안건이 이 항목의
  확정 권한을 TL 에게 위임했습니다 (PR #289, 2026-08-27 머지). 미결정 대장 N22 를 닫습니다

## 배경

만화형 시안 화면이 제출까지 열리지 않을 상태였습니다. 뒤는 도는 것이 확인됐는데
([만화형_실물_검증_보고서.md](../보고서/만화형_실물_검증_보고서.md), 2026-08-26 배포 스택에서
실물 1회로 6칸 대사, 렌더 3456 x 2304, 화면 표시, 다운로드까지 통과), 화면 앞쪽 게이트를
걷을 수 없었기 때문입니다.

게이트를 걷지 못한 이유는 그 뒤의 스텁입니다. 기본 설정(`ADGEN_GENERATION_MODE=stub`)으로 도는
사람이 만화형을 누르면 `_generate_stub` 이 거절하고, 그 거절이 라우트에서 503
`UPSTREAM_UNAVAILABLE` 이 되어 화면에 "생성 엔진에 연결하지 못했습니다" 로 도착했습니다.
**문제는 실패한다는 것이 아니라 그 실패가 실장애와 구분되지 않는다는 것**이었습니다.

계약에는 생성 모드를 알려 주는 필드가 없습니다(`openapi.yaml` 검색 0건). 그래서 "실물일 때만
열기" 라는 조건부 분기가 화면 쪽에서 성립하지 않았습니다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 가. 이 경로에만 다른 오류 코드를 준다 | 실패의 이름이 정확해집니다. 06 잠정안이었습니다 | 계약이 우리 개발 환경(설정값)을 서술하게 됩니다. 실물에서는 절대 발생하지 않는 코드이고, 실물 전환 뒤에는 계약까지 되돌려야 합니다 |
| 나. 그냥 열고 스텁에서의 실패를 받아들인다 | 코드 변경이 없습니다 | 없는 장애를 있다고 말합니다. 게이트가 애초에 막으려던 것이 이것입니다 |
| 다. 계약에 생성 모드를 노출한다 | 화면이 모드를 알고 분기할 수 있습니다 | 가장 무겁습니다. 서비스 계약에 배포 설정을 싣는 것이기도 합니다 |
| **라. 스텁이 만화형 여섯 칸을 채운다** | 실패 자체가 없어집니다. 계약도 backend 도 건드리지 않습니다 | `draft.py` 주석이 명시적으로 반려해 둔 방향이었습니다 |
| 마. 게이트를 닫은 채 제출한다 | 아무 위험이 없습니다 | 만화형 화면이 끝내 열리지 않습니다 |

## 결정

**라를 택합니다.** 스텁이 만화형 여섯 칸을 채우고, 부분 교체도 같은 규칙으로 처리합니다.

### 반려 사유의 전제가 이미 사라졌습니다

`draft.py` 의 반려 문장은 "Faking six panels would make the comic path look finished" 였고,
그것이 쓰인 시점에는 **실물 분기가 비어 있었습니다.** 지금은 다릅니다.

- 실물 만화형 분기는 2026-08-20 에 들어왔고(PR #145, #150,
  [ADR-0017](0017-만화형은_칸을_따로_생성해_합성한다.md)), 2026-08-26 실물 1회로 통과했습니다.
- 같은 파일의 실물 분기 주석이 이미 같은 논리를 적어 두었습니다 - "칸 수와 역할은 계약과 기획서
  7.3 이 정해 두었으므로 여기서 새로 정하는 값이 없습니다". 스텁도 마찬가지입니다. 칸 수 6 은
  `ComicDraft` 가, 역할 순서는 `PANEL_ROLES` 가 강제하므로 스텁이 지어내는 구조값이 없습니다.
- `test_a_comic_patch_cannot_name_the_single_ad_fields` 가 그 유효기간을 스스로 적어 두었습니다 -
  "a property of the skeleton, not of the contract, and would disappear the moment the comic
  branch is written". 그 순간이 지났습니다.

즉 이 결정은 반려된 방향을 뒤집는 것이 아니라 **반려 조건이 해제된 것을 반영하는 것**입니다.

### 수정 비용도 라가 적습니다

회의가 정한 판단 기준이 "실제 수정 비용이 더 적은 쪽" 이었습니다.

| | 라 (스텁이 여섯 칸) | 가 (다른 오류 코드) |
|---|---|---|
| 계약 | 변경 없음 | `draft:generate` 와 `draft:patch` **두 이음매**에 새 실패 응답 |
| ai-engine | 함수 둘 | 이음매 전용 예외 신설 + 라우트 둘 + 반대를 명시한 주석 둘 |
| backend | 없음 | `ai_client` 상태 매핑, `api/errors.py`, `backend_core/models/common.py` |
| frontend | 게이트 제거 | 게이트 제거 + 오류 코드 분기 + 문구 |
| 렌더 | 이미 만화형 규격을 받습니다(`_render_stub`) | 같음 |
| 실물 전환 뒤 | 남는 것이 없습니다 | 계약을 포함해 전부 되돌려야 합니다 |

덤으로 얻는 것이 하나 있습니다. 지금까지 스텁으로는 만화형을 한 번도 지나갈 수 없어 `e2e/` 에
만화형 커버리지가 0건이었는데, 이제 외부 API 비용 없이 관통을 고정할 수 있습니다.

### 채우되 결과물로 보이지 않게 하는 조건 넷

원래 반려 사유 중 살아 있는 절반은 "스텁 산출물이 결과로 오인되는 사고" 입니다. 이것은 단일
광고형 스텁이 이미 쓰고 있는 장치로 막습니다.

1. 여섯 칸 전부(`scene`, `dialogue`)와 `adPlan` 에 `stub_marker` 를 답니다.
2. 문구는 `sellingPoint` 와 제품명에서만 만듭니다. 추론값(`category`, `target`)은 쓰지 않습니다.
3. **숫자를 쓰지 않습니다.** 칸 번호를 문구에 적으면 근거에 없는 수치가 되어, 스텁 회차로
   가드레일을 돌렸을 때 우리가 만든 숫자가 위반으로 잡힙니다
   ([ADR-0019](0019-광고_카피_가드레일은_금지_표현을_검출한다.md)).
4. 여섯 칸의 대사는 같습니다. 칸마다 다른 문장을 쓰려면 소구점에 없는 말을 지어내야 하고,
   반복 자체가 스텁이라는 표시이기도 합니다.

렌더 쪽은 손대지 않습니다. `_render_stub` 이 만화형 규격을 그대로 받아 대각선이 그어진
자리표시자를 돌려주므로, 화면에 도착하는 이미지도 실물로 오인될 수 없습니다.

## 결과

- `_generate_stub` 이 만화형이면 여섯 칸을 채우고, `_patch_stub` 이 지목된 칸의 지목된 부분만
  갈아 끼웁니다. 부분 교체를 함께 여는 이유는, 화면이 만화형을 열어 둔 채 부분 교체만 503 으로
  죽으면 같은 문제가 절반만 옮겨 가기 때문입니다.
- **계약은 바뀌지 않습니다.** backend 도 바뀌지 않습니다.
- `NotImplementedError` 를 잡는 자리(`service.py`, `eval/run_collect_ad_copy.py`)는 남겨 둡니다.
  지금 그 갈래를 타는 경로는 없고, 다음 미구현 분기를 위한 그물입니다.
- **화면 게이트 제거는 이 ADR 의 범위가 아닙니다.** 06 소관이며 추적은 이슈 #271 입니다.
- **스텁 회차의 가드레일 위반 건수는 지표가 아닙니다.** 스텁 문구는 소구점을 그대로 옮긴 것이라
  언제나 통과합니다. on/off 대조에 쓸 수 있는 회차는 여전히 실물 모드뿐입니다
  (`eval/run_collect_ad_copy.py` 머리말).
- 재검토 신호는 둘입니다. 스텁 산출물이 보고서나 실측 표에 결과로 실린 것이 발견될 때, 그리고
  계약에 생성 모드가 다른 이유로 노출될 때입니다. 뒤가 일어나면 "가" 와 "다" 의 비용 계산이
  달라집니다.
