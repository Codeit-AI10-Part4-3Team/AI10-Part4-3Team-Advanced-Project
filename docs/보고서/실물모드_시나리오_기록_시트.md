## 1. 시작 전

`.env` 에 두 줄이 있어야 합니다.

```
ADGEN_GENERATION_MODE=model
ADGEN_MODEL_API_KEY=<키>
```

**타임아웃은 넣지 않습니다.** 기본값이 25초 / 30초입니다 (PR #329). 아래 확인 줄로 그 값이
실제로 들어갔는지만 봅니다.

```bash
cd /srv/adcraft/app
C="docker compose -f infra/docker-compose.yml"

$C logs ai-engine | tail -20 | grep "generation seams"   # 'model' mode
$C exec ai-engine sh -c 'echo engine=$ADGEN_BRIEF_FILL_MODEL_TIMEOUT_S'   # 25.0
$C exec backend   sh -c 'echo backend=$ADGEN_BRIEF_FILL_TIMEOUT_S'        # 30.0
$C exec ai-engine sh -c 'echo keylen=${#ADGEN_MODEL_API_KEY}'   # 0 이 아님
$C exec backend python -c "import json,os;print(len(json.loads(os.environ['ADGEN_ART_STYLES'])))"   # 8
$C exec backend sh -c 'ls /data/art-styles | wc -l'      # 8

# 키가 모델에 실제로 닿는가. 안 보면 첫 유료 호출인 S01 에서 처음 알게 됩니다
$C exec ai-engine python -c "import os;from openai import OpenAI;print(len(OpenAI(api_key=os.environ['ADGEN_MODEL_API_KEY']).models.list().data))"

# 품질 override 가 비었는가. 값이 있으면 만화형이 medium 이 아닌 티어로 돕니다
$C exec ai-engine sh -c 'echo "override=[${ADGEN_IMAGE_QUALITY_OVERRIDE}]"'

# 08-29 프롬프트가 실제로 배포됐는가. 'draft-v2' 가 아니면 옛 칸 지시로 돕니다
$C exec ai-engine python -c "from ai_engine import draft_prompt; print(draft_prompt.VERSION)"
```

마지막 셋도 요금 0 입니다. **`override=[]` 가 아니면 멈추십시오** - 값이 있으면 요청의 티어를
덮어쓰고 경고 로그만 남기므로, 만화형 8세션이 다른 티어로 돌아 단가 표와 화풍 축이 함께
어긋납니다. 증상은 "결과가 좀 흐리다" 뿐이라 회차가 끝날 때까지 모릅니다.

**`draft-v2` 가 아니어도 멈추십시오** - 배포된 코드가 2026-08-29 조치 이전이라는 뜻이고,
그러면 1번 칸에 제품이 없는 옛 칸 지시로 돕니다 (생성_파이프라인 4.2절). 4절의 판정 열
셋이 통째로 다른 조건의 값이 되며, 이것도 결과만 보고는 알 수 없습니다.

**셋째 줄과 넷째 줄은 다른 것을 봅니다.** 셋째는 **카탈로그 설정값**이 제대로 파싱되는지이고,
넷째는 볼륨의 **예시 이미지 파일** 수입니다. 키를 `.env` 에 넣을 때 개행을 빠뜨리면 키가
`ADGEN_ART_STYLES` 값 끝에 이어 붙는데, **그 사고는 셋째 줄만 잡습니다** - 이미지 파일은
멀쩡하므로 `ls` 는 그대로 8을 돌려줍니다.

화면에서 화풍 격자가 **8칸** 다 보이는지도 눈으로 확인합니다. 하나라도 어긋나면 멈춥니다.

## 4. 만화형만 - 여섯 칸 보고 한 줄

| 회차 | 1번 칸 제품 + 주배경 | 앞 칸 사용 장면 (칸 번호) | 여섯 칸 포장 장소 일치 | 최장 대사 (자) | 오탈자 | 인물 유지 |

| S04 | O | X | O | 10 | 없음 | O |

| S11 | O | X | O | 11 | 없음 | O |

**2026-08-29 조치로 판정이 바뀌었습니다** (생성_파이프라인 4.2절). 제품은 1번 칸부터 여섯
칸 모두에 놓여 있는 것이 정상이므로, "앞 칸에 제품이 나왔는가" 로 적지 않습니다.

- **1번 칸 제품 + 주배경**: 1번 칸에 제품과 주배경이 함께 그려졌으면 O 입니다. 나머지 다섯
  칸이 이 칸만 레퍼런스로 보므로, 여기가 X 면 아래 두 열은 볼 것이 없습니다
- **앞 칸 사용 장면**: 1 ~ 3번 칸에서 인물이 제품을 들거나 꺼내거나 쓰고 있으면 O 이고 칸
  번호를 함께 적습니다. 놓여 있기만 한 것은 X 입니다 (정상). N26 이 묻는 축입니다
- **여섯 칸 포장 장소 일치**: 여섯 칸의 제품 포장 모양과 장소가 서로 같으면 O 입니다.
  조치 전에는 고정되지 않는 것이 알려진 한계였고, 이 열이 그것을 처음 재는 자리입니다

대사 25자 상한은 지침뿐이고 검사 코드가 없어 넘겨도 통과합니다 - 실제로 몇 자인지가
이 열의 전부입니다.

**S06 의 셋째 열이 X 인 근거**는 3절 메모입니다 - 1번 칸 불판에 있던 고기가 2번 칸에서
사라졌습니다. 제품이 한 칸에서 없어진 것은 "여섯 칸의 포장과 장소가 서로 같다" 가 아닙니다.

**S07 의 관측은 제품이 두 자리에 동시에 있는 것입니다** - 5, 6번 칸에서 인물이 모자를 썼는데
벤치에도 모자가 그대로 남아 있습니다. 인물과 배경이 각각은 유지됐으나 제품이 복제됐습니다.

**계획서 F-b 7(`note` 갈래별 반영도): 네 갈래 모두 반영됐습니다.**

| 회차 | 갈래 | `note` 반영 |
|---|---|---|
| S06 | 배경 지정 (가족이 둘러앉은 식탁) | O |
| S07 | 인물 지정 (20대 대학생) | O |
| S08 | 캐릭터 지정 (북극곰) | O |
| S09 | 상황 지정 (시험 기간에 집중) | O |

**칸 단위로는 세지 않았습니다.** 계획서 F-b 7 이 물은 "배경이 몇 번째 칸까지 유지되는가",
"북극곰이 여섯 칸 모두에 나오는가" 는 따로 기록하지 않았고, 위 표는 요청한 것이 결과에
나타났는지까지입니다.

**`Brief.character` 를 채우는 경로가 없는데도 S08 이 O 라는 것이 이 표의 값입니다.**
`brief:fill` 이 캐릭터를 추출하지 않아 `brief.character` 가 늘 비어 있고, 화면의 외모와 복장
입력은 그 값이 있을 때만 그려집니다(`BriefSummary.tsx`). **입력칸이 없는 것이 아니라 채우는
경로가 없어 가려져 있는 것입니다.** 그래서 만화형에서 캐릭터를 지정하는 통로는 `note` 자유
텍스트 하나뿐입니다 (계획서 C-b-1절).

## 5. 가드레일 한 번

**화면에서 이 입력으로 시안까지만 만들어 봅니다.** `확정` 을 누르지 않으면 이미지 요금이

**계획서 D-d 의 조합과 다릅니다.** 계획은 `대나무 물티슈` / `무향 무알코올` 이었고 실제로
친 것은 위와 같습니다. 방아쇠인 "상을 받았습니다" 는 그대로라 조건이 사라지지는 않았지만,
**아래 재현율 7/12 는 물티슈 조합에서 잰 값이라 이 1건에 그대로 적용되지 않습니다.**

근거에는 "상을 받았습니다" 가 있는데 카피가 **"수상"** 이라고 쓰면 걸립니다.

| 나온 카피 | 거절됐나 | |
|---|---|---|
| 멋을 쓰다, 아디다스 모자. | 거절되지 않음 | |

거절 화면이 뜨면 캡처하십시오. 안 걸릴 수도 있습니다 (재현율 7/12).

**on/off 대조는 화면으로 못 합니다** - 운영 경로는 항상 on 입니다. 그 대조는
[가드레일 대조 실측 보고서](가드레일_대조_실측_보고서.md)에 이미 있습니다 (양 팔 30건씩).

**S01 ~ S19 카피에 이상한 문구가 있었나** (없는 수치, 타사 비교, 최상급, 수상):

**없습니다. 19건 전부 `위반 X` 입니다** (회차별 판정은 3절 메모 열).

**검출기 기준입니다.** 소구점에 넣은 가상 사양(`350ml`, `0.5mm`, `1kg` 등)은 근거 안에 있어
카피가 그대로 인용해도 위반이 아닙니다. 실존 브랜드에 대한 가상 사양을 인용한 카피가 이 안에
들어 있을 수 있습니다 (계획서 D-d절).

남아 있습니다.** 2026-08-31 발표에서 실물 생성을 보이려는 것이 이유입니다.

**유지 여부와 끄는 시점을 이 문서가 정하지 않습니다.** 2026-08-24 회의(안건 02)가 "코드로
호출 횟수나 금액 상한을 만들지 않는다" 와 "실측 회차(08-26 ~ 28) 동안만 켠다" 를 **한 쌍으로**
두었고, 계획서 머리 표도 "회차 동안만 켜고 끝나면 되돌립니다" 입니다. 그 기간을 넘겨 유지하려면
**소관자(05, 01) 확인을 거쳐 회의록이나 이슈 #291 에 남아야 합니다** - 근거 자료 규칙 2와 5.

같은 회의록이 위험도 이미 적어 두었습니다. `model` 로 두는 동안은 **상한 없는 공개 서비스**이고,
키는 VM 디스크에 평문으로 남습니다. `infra/.env` 는 `.gitignore` 대상이라 커밋 경로로 새지는
않습니다.

### 되돌리는 절차 (끄기로 정해지면)

`/srv/adcraft/app/infra/.env` 를 편집기로 열고 두 줄을 되돌립니다.

- `ADGEN_GENERATION_MODE=model` 을 `stub` 으로 고치거나 줄째 지웁니다 (없으면 기본값이 `stub`)
- `ADGEN_MODEL_API_KEY=` 줄을 **줄째 지웁니다**

저장할 때 상태바가 **`LF`** 인지 봅니다. `CRLF` 면 값 끝에 캐리지 리턴이 붙어 ai-engine 이
기동하지 않습니다.

```bash
cd /srv/adcraft/app && bash scripts/deploy-vm.sh --no-build

C="docker compose -f infra/docker-compose.yml"
$C logs ai-engine | tail -20 | grep "generation seams"   # 'stub' mode
$C exec ai-engine sh -c 'echo keylen=${#ADGEN_MODEL_API_KEY}'   # 0
grep -rln 'sk-' infra/ 2>/dev/null                       # 아무것도 안 나와야 정상

ls infra/.env.bak-* 2>/dev/null && shred -u infra/.env.bak-*
```
