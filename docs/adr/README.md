# ADR (Architecture Decision Records)

구조·기술에 관한 **결정과 그 배경**을 남기는 곳입니다. 문서화되지 않은 결정은 결정한 사람이
자리를 비우는 순간 사라지고, 남은 팀은 같은 논의를 처음부터 다시 합니다.

## 언제 쓰나

- 되돌리는 비용이 큰 선택을 했을 때 (레포 구조, 배포 형태, 저장소, 주요 라이브러리)
- **하지 않기로** 결정했을 때 — 이쪽이 더 자주 잊힙니다
- 코드만 봐서는 "왜 이렇게 했는지" 알 수 없는 제약을 도입했을 때

반대로, 코드를 읽으면 드러나는 것(함수 구조, 네이밍)은 ADR 대상이 아닙니다.

## 규칙

- 파일명은 `NNNN-한글_제목.md` (숫자는 연번, 다단어는 밑줄). `docs/역할_가이드/`와 같은 꼴입니다.
  제목은 파일 안의 H1과 뜻이 같아야 합니다 — 목록에서 고른 문서가 다른 이야기를 하면 색인이
  쓸모없어집니다.
- **번호는 재사용하지 않습니다.** 폐기된 ADR의 번호도 비워 둡니다. 링크가 다른 결정을 가리키게
  되는 것이 빈 번호보다 나쁩니다.
- 한 파일에 **결정 하나**. 여러 결정을 묶으면 나중에 하나만 뒤집을 수 없습니다.
- 결정을 뒤집을 때는 기존 ADR을 **고치지 말고** 새 ADR을 쓰고 `Superseded by`로 연결하세요.
  틀린 판단의 기록도 자산입니다.
- **`Accepted` ADR의 본문은 보존합니다. 예외는 하나입니다** (2026-08-27 확정) - **이 프로젝트의
  계약에 존재한 적이 없는 이름**은 본문에서 치환하고 날짜가 붙은 정정 주석을 답니다. 적용
  대상인지는 `git log -S '<이름>'`으로 이력을 확인해 가립니다. 취향이 아니라 사실이 가르게
  하려는 것입니다. 근거는
  [2026-08-27 회의록](../회의록/2026-08-27_안건_12건_확정.md) 12번 안건이고, 이 예외로 처리된
  첫 사례는 PR #264(`unsupported_claim`)입니다.
- 양식은 [0000-템플릿.md](0000-템플릿.md)를 복사해서 쓰세요.

## 아직 쓰이지 않은 ADR (결정 대기)

되돌리는 비용이 크므로 **결정하는 즉시** ADR로 남기세요.

**2026-08-20 기준으로 대기 중인 항목은 없습니다.** 두 행 다 조건이 소멸했고, 표를 지우지 않고
취소선으로 남기는 이유는 "왜 안 쓰기로 했는가"가 다음 사람에게 필요하기 때문입니다. 빈 표를
보고 "아무도 안 적었다"로 읽는 것과 "쓸 것이 없다"로 읽는 것은 다릅니다.

| 주제 | 언제 쓰나 | 왜 ADR인가 |
|---|---|---|
| ~~로컬 모델 채택 시의 어댑터 설계~~ | **쓰지 않습니다** | 조건이 "검증 4순위에서 로컬 모델을 **채택하면**" 이었는데 2026-08-20 회의가 **미채택**으로 닫았습니다 ([회의록](../회의록/2026-08-20_검증4순위_로컬모델_미채택.md), 미결정_대장 A-5). [ADR-0003](0003-이미지_생성_경로.md)과 [ADR-0004](0004-파인튜닝_보류.md)는 뒤집히지 않고 그대로 섭니다. **되살리려면** 그 확정을 뒤집는 새 회의록이 먼저입니다 |
| ~~카피 생성 경로 (외부 LLM API / 로컬 모델)~~ | **쓰지 않습니다** | 2026-08-19 회의가 기획서 13.2(텍스트와 이미지 모두 GPT API)를 **그대로 유지**하기로 확인했습니다 ([회의록](../회의록/2026-08-19_소관배정_화풍확정_카피경로확인.md) 3번). 새 결정이 아니라 기존 근거의 유지 확인이므로 ADR이 필요하지 않습니다. **뒤집을 때** 씁니다 |
