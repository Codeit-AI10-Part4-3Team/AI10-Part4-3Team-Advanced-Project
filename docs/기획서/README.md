# 기획서

## 정본은 마크다운입니다

| 구분 | 대상 | 위치 |
|---|---|---|
| 정본 (source of truth) | [기획서.md](기획서.md) | 저장소에 커밋. PR에서 줄 단위 diff |
| 배포 산출물 (artifact) | PDF | 커밋하지 않음. GitHub Release에 첨부 |

PDF는 바이너리라 diff가 나오지 않고, 개정할 때마다 파일 전체가 저장소 이력에 영구히
쌓입니다. 기획서 변경이 리뷰 대상에서 빠지는 것이 더 큰 문제이므로 정본을 마크다운으로 둡니다.
`docs/기획서/*.pdf`는 루트 `.gitignore`에서 무시됩니다.

버전 구분은 파일명이 아니라 **태그**가 합니다. `proposal_v1.pdf`, `proposal_v2_final.pdf`
같은 파일명 버전 관리는 하지 않습니다.

## 개정 절차

1. `기획서.md`를 피처 브랜치에서 수정하고 PR을 올립니다. 근거가 된 회의록을 PR 본문에
   연결합니다 (기획서 14.3의 문서 관리 원칙).
2. 팀 합의 후 squash merge 합니다.
3. 판본을 고정해야 하는 시점(전원 합의, 중간 점검, 제출)에만 태그를 답니다.
4. 필요하면 그 시점의 PDF를 만들어 Release 자산으로 첨부합니다.

```bash
# main 에 머지된 상태에서 실행합니다. 태그가 그 시점의 기획서.md 를 가리킵니다.
git tag -a proposal-v0.7 -m "기획서 v0.7 - 팀 합의본"
git push origin proposal-v0.7
gh release create proposal-v0.7 \
    --title "기획서 v0.7" \
    --notes "정본: docs/기획서/기획서.md (태그 proposal-v0.7 시점)" \
    docs/기획서/proposal-v0.7.pdf
```

## 알려진 사항

- 전환 전 PDF는 표지에 `시안 v0.7`, 파일 메타데이터 제목에 `v0.6`, 파일명에 `v1`이 각각
  적혀 있었습니다. 세 값이 어긋나 있어 문서 본문의 표기인 **v0.7**을 채택했습니다.
- 전환은 내용 보존을 원칙으로 했습니다. 문체는
  [문서_작성_규약.md](../공통_가이드/문서_작성_규약.md)에 맞춰 경어체로 바꿨고,
  가운뎃점과 화살표 등 키보드로 입력할 수 없는 문자는 치환했습니다. 흐름도 두 개는
  mermaid로 옮겼으며, 12.2의 화면 배치도는 와이어프레임 대체 전까지 코드 블록으로 둡니다.
