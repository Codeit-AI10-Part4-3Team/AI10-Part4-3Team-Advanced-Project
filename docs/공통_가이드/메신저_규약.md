# 메신저 규약

팀 메신저(카카오톡, 슬랙, 디스코드)에 **보낼 텍스트를 어떻게 쓰는가**에 대한 규약입니다.
저장소 안에 남는 글(PR 본문, 이슈, 리뷰 코멘트, 문서)은 대상이 아닙니다.

| 쓰는 곳 | 따르는 문서 |
|---|---|
| 팀 메신저 | 이 문서 |
| PR 리뷰 코멘트 | [코드_리뷰_가이드.md](코드_리뷰_가이드.md) |
| 기획서, 기술문서, ADR | [문서_작성_규약.md](문서_작성_규약.md) |

메신저는 저장소가 아닙니다. **여기서 오간 말은 근거가 아닙니다**
([AGENTS.md](../../AGENTS.md) 근거 자료 규칙: DM과 구두 발언은 비근거). 합의한 내용은 이슈,
회의록, ADR 중 하나로 옮겨야 효력이 생깁니다. 이 규약이 메시지를 짧게 묶어 두는 이유이기도
합니다. 길게 쓸 내용이라면 애초에 메신저가 아니라 저장소에 들어가야 합니다.

## 1. 첫 줄이 결론입니다

**무엇을, 누가, 언제까지.** 인사말, 배경 설명, 맺음말을 넣지 않습니다.

읽는 사람은 알림 미리보기에서 첫 줄만 봅니다. 첫 줄이 "안녕하세요 다름이 아니라"면 그 알림은
열어 보기 전까지 아무 정보도 전달하지 못합니다.

## 2. 상세는 링크 뒤에 둡니다

근거, `file:line`, 대안, 재현 절차는 PR, 이슈, 문서 링크로 넘깁니다. 본문에 붙이지 않습니다.

메신저 본문은 검색되지 않고 버전이 없으며 스크롤에 묻힙니다. 같은 내용을 링크 대상과 본문에
두 벌 두면 이틀 뒤에 둘이 다른 말을 합니다.

## 3. 천장: 5줄

- 5줄, 한글 약 250자를 넘기지 않습니다.
- 불릿은 최대 3개, 중첩하지 않습니다. 첫 줄 결론까지 합쳐 5줄 안에 들어와야 합니다.
- 문단마다 줄바꿈합니다. 이 채널들은 개행이 그대로 살아납니다.

250자인 이유는 폰 화면입니다. 카카오톡 기본 설정에서 한 줄에 들어가는 한글이 20 ~ 25자이므로
(`높은 신뢰`), 250자면 화면에서 10줄 안팎이고 스크롤 없이 한 화면에 들어옵니다. 글자 수를 두 배로
잡으면 화면에서는 20줄이 넘어가 4절의 점검을 통과할 수 없습니다.

천장을 넘겼다면 문장을 줄일 것이 아니라 **링크 대상에 들어갈 내용이 본문에 있는 것**입니다.

## 4. 보내기 전 점검

- 폰 화면에서 스크롤 없이 읽히는가.
- 읽은 사람이 **자기가 다음에 할 일**을 아는가.

두 번째가 핵심입니다. 아무 행동도 요구하지 않는 공유라면 그 사실을 한 마디로 밝힙니다
("공유만, 조치 불필요").

## 5. 리뷰 결과를 공유할 때

리뷰 본문은 PR에 남기고, 메시지에는 **판정과 링크만** 보냅니다. 이 규약이 리뷰 서식보다
우선합니다.

처리 등급(`머지 전 필수` / `이 PR에서 권장` / `후속 과제` / `참고, 조치 불필요`)은
[코드_리뷰_가이드.md](코드_리뷰_가이드.md) 2-b의 라벨을 글자 그대로 씁니다. 메시지에는 가장
높은 등급 하나와 건수만 적습니다.

## 6. 예시

리뷰 요청:

```
#42 리뷰 부탁드립니다. 백엔드 잡 큐 스켈레톤입니다.
계약(openapi.yaml)이 같이 바뀌어서 TL 승인이 필요합니다.
https://github.com/.../pull/42
```

리뷰 결과 공유:

```
#42 리뷰 남겼습니다. 머지 전 필수 1건(brief:fill 열화 누락), 나머지 2건은 후속 과제입니다.
https://github.com/.../pull/42#pullrequestreview-...
```

장애, 환경 공유:

```
GPU VM 재기동했습니다. 08-17 14:00까지 학습 잡만 돌립니다.
그동안 시안 생성은 503으로 실패합니다. 공유만, 조치 불필요.
```

나쁜 예:

```
안녕하세요! 오늘 작업하다가 궁금한 게 생겨서요. 어댑터 로딩 부분을 보는데
generator.py 48번째 줄에서 예외 처리가 없더라고요. 그래서 제가 생각하기로는
try except 로 감싸는 게 맞을 것 같은데 아니면 상위에서 잡는 방법도 있고...
```

무엇을 요청하는지, 누가 답해야 하는지, 언제까지인지가 없습니다. 이 내용은 메시지가 아니라
PR 코멘트에 들어갈 것입니다.
