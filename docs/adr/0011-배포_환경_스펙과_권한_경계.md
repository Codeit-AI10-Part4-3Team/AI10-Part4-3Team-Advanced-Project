# ADR-0011: GCP VM은 학원이 배정한 스펙과 권한을 그대로 받습니다

- **상태**: Accepted
- **날짜**: 2026-08-10
- **결정자**: 신호정 (TL)
- **관련**: [ADR-0010](0010-상태_저장소와_파일_보관_위치.md), [리스크.md](../공통_가이드/리스크.md) 9번,
  [착수_체크리스트.md](../공통_가이드/착수_체크리스트.md) 5절, [infra/README.md](../../infra/README.md)

## 배경

[AGENTS.md](../../AGENTS.md)의 TBD 목록에 "GCP VM 스펙(GPU, VRAM)"이 남아 있었습니다. 확인해
보니 이 항목은 우리가 고르는 것이 아니라 **학원이 배정한 것**이었습니다. 고를 수 없는 항목을
TBD로 두면 결정을 기다리는 사람이 계속 생깁니다.

**배정된 스펙** (변경 불가)

| 항목 | 값 |
|---|---|
| 리전 | `us-central1` |
| 머신 타입 | `g2-standard-4` (vCPU 4, 호스트 RAM 16GB) |
| GPU | NVIDIA L4 1장. 가용 VRAM **23,034MiB (약 22.5GB)** (2026-08-10 실측, 공칭 24GB 아님) |
| 부팅 디스크 | 100GB |
| OS | **우리가 선택** |
| 스냅샷 일정 | UTC 18:00 ~ 19:00 (KST 03:00 ~ 04:00) |

**권한과 비용** (2026-08-10 실측)

- 결제 계정은 학원 소유입니다. 예산 알림, 지출 상한, 잔여 크레딧 조회 권한이 우리에게 없습니다.
- 프로젝트 IAM에서 우리 계정이 가진 역할은 커스텀 역할 하나뿐입니다 (`sprinter_vm_role_v1`).
  **그 역할의 정의를 읽을 권한조차 없어서**(`iam.roles.get` 거부) 무엇이 되고 무엇이 안 되는지를
  목록으로 받을 수 없습니다. 범위는 실측으로만 알 수 있고, 결과는
  [infra/README.md](../../infra/README.md)에 기록합니다.
- 프로젝트 수준 조직 정책은 0건이고, 외부 IP 부여는 허용(`ALLOW`)입니다. 브라우저에서 접속하는
  구성이 성립한다는 뜻이며, 이것이 확인되지 않았다면 접근 경로 설계를 다시 해야 했습니다.
- 이미지 프로젝트 제한도 없어서 **OS 이미지는 자유롭게 고를 수 있습니다.**
- 다만 서비스 계정 키 발급은 조직 수준에서 **금지**되어 있습니다
  (`iam.disableServiceAccountKeyCreation`이 적용됨).

제약이 서로 묶여 있다는 점이 중요합니다. 머신 타입은 GPU와 vCPU와 RAM이 한 묶음이라 **메모리만
늘릴 수 없고**, 디스크 확장에도 권한이 필요하므로 **100GB를 상한으로** 보아야 합니다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. **배정 스펙을 고정 제약으로 받고 설계를 맞춘다** | 지금 바로 설계를 진행할 수 있음. 제출 환경과 개발 환경이 일치 | 스펙이 부족하면 범위를 줄이는 것 외에 방법이 없음 |
| B. 상향을 요청하고 승인까지 설계를 보류 | 되면 여유가 생김 | 승인 여부와 시점을 우리가 통제하지 못함. 22일 일정에서 대기는 그대로 손실 |
| C. 개인 결제 계정으로 별도 프로젝트를 만든다 | 권한 제약이 사라짐 | 비용을 개인이 부담. 제출물의 실행 환경이 학원 환경과 달라져 재현이 성립하지 않음 |

## 결정

**A를 택합니다.** 스펙과 권한은 협상 대상이 아니라 **입력값**입니다.

- **비용은 리스크 관리 대상에서 뺍니다.** 감지 수단도 대응 수단도 없는 항목을 리스크 표에 두면,
  대응이 적혀 있다는 이유로 관리되고 있다고 착각하게 됩니다. 남는 것은 "크레딧이 예고 없이
  소진될 수 있다"는 사실 하나이고, 대비는 산출물을 미리 내려받아 두는 것뿐입니다.
- **OS만 우리 선택입니다.** 드라이버와 CUDA 설치에 하루를 쓰지 않는 쪽을 고릅니다. 구체적인
  이미지 선택과 근거는 [infra/README.md](../../infra/README.md)에 남깁니다.
- **권한이 막힌 항목은 우회하지 않고 기록합니다.** 우회 구성은 재현 절차를 학원 환경과
  갈라놓습니다.

B를 택하지 않은 이유는 **대기 시간을 우리가 통제하지 못하기 때문**입니다. 실작업 22일에서
승인 대기는 일정 직격입니다.

C를 택하지 않은 이유는 **제출물의 실행 환경이 달라지기 때문**입니다. 공개 저장소에 개인 결제
계정을 엮는 것도 되돌리기 어려운 선택입니다.

## 결과

**생기는 제약**

1. **호스트 RAM 16GB가 상한입니다.** VRAM보다 호스트 RAM이 먼저 부족해질 수 있습니다. 가중치를
   CPU에 올린 뒤 GPU로 옮기는 로더, dataloader worker, 오프로드 경로가 모두 여기를 씁니다.
   **swap을 반드시 잡습니다.** 없으면 OOM killer가 컨테이너를 조용히 죽입니다.
2. **디스크 100GB가 상한입니다.** base 모델 가중치, Docker 이미지, 학습 체크포인트, 7일치 결과
   이미지가 전부 이 안에 들어가야 합니다. 디스크 사용률 감시가 선택 사항이 아닙니다.
3. **ADR-0003(이미지 생성 경로)의 입력 예산이 확정됩니다.** 가용 VRAM 22.5GB, 호스트 RAM 16GB,
   디스크 100GB를 넘는 후보는 검토 대상에서 뺍니다. **어떤 모델을 고를지는 ADR-0003의 몫이고,
   이 ADR은 예산만 정합니다.** 공칭 24GB를 기준으로 "겨우 들어간다"고 판단한 후보는 실제로는
   들어가지 않으니 실측값을 쓰세요.
4. **워커 프로세스는 1개를 유지합니다.** [ADR-0010](0010-상태_저장소와_파일_보관_위치.md)이 SQLite
   쓰기 잠금을 이유로 이미 정한 것과 같은 결론이지만, 근거가 하나 더 붙습니다. vCPU 4개를 학습과
   추론과 백엔드가 나눠 씁니다.
5. **비용을 이유로 VM을 정지하지 않습니다.** 상시 기동이 기본입니다. 정지는 GPU 시간 분할
   규칙(리스크 1번)이 요구할 때만 합니다.
6. **Spot 인스턴스를 쓰지 않습니다.** 절감할 비용이 우리 것이 아닌데 회수 위험만 떠안습니다.
7. **배포 자동화에 서비스 계정 키를 쓸 수 없습니다.** 조직 정책이 키 발급을 막고 있으므로,
   GitHub Actions에서 VM으로 배포하는 워크플로를 계획에 넣지 마세요. 배포는 SSH 접속 후
   `git pull`과 `docker compose up`의 수동 경로이며, 그 절차를
   [infra/README.md](../../infra/README.md)에 남깁니다. VM 안에서 그 VM의 서비스 계정으로
   GCP API를 호출하는 것은 키가 필요 없으므로 영향받지 않습니다.
8. **권한 목록을 문서로 받을 수 없으므로 실측 기록이 유일한 근거입니다.** "될 것 같다"로
   계획하지 말고, 배포 주간 전에 실제로 만들어 보고 그 결과를 기록하세요.

**쉬워지는 것**

- 비용 설계가 통째로 사라집니다. 예산 알림 연동, 자동 정지 스케줄, 인스턴스 종류 비교를 만들
  이유가 없습니다.
- 환경 변수가 하나로 고정되므로 "내 환경에서는 되는데"가 줄어듭니다.

**어려워지는 것**

- 크레딧이 소진되면 예고 없이 멈추고, 우리는 그 시점을 미리 알 수 없습니다. 시연과 발표에 쓸
  산출물을 보존 기간과 무관하게 **미리 내려받아 두는 것**이 유일한 대비입니다
  ([세션_보관_정책.md](../기술문서/세션_보관_정책.md) 2절과 같은 지침입니다).
- 스펙이 부족하다고 판명되면 대응은 범위 축소뿐입니다. 그래서 학습 1회전 소요 시간을 W1에
  실측해야 합니다.

**재검토 신호**

- 커스텀 역할 범위를 확인한 결과 **배포에 필요한 권한이 빠져 있을 때**. 이때는 우회가 아니라
  학원에 요청하고, 요청과 결과를 기록합니다.
- 학원이 스펙 변경을 허용할 때.
- 학습 1회전 실측이 일정 안에 들어오지 않을 때. 이 경우 바꿀 것은 스펙이 아니라 학습 범위입니다.
