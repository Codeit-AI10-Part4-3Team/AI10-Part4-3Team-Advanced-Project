# ADR-0009: 브리프는 시안 생성과 함께 잠기고, 광고 기획안은 고칠 수 없다

- **상태**: Accepted
- **날짜**: 2026-08-09
- **결정자**: 신호정 (TL) 제안, 정승호 (PM) 확인 (PR #39 리뷰)
- **관련**: [도메인_모델.md](../기술문서/도메인_모델.md) 7절 (INV-7, INV-8),
  [API_계약.md](../기술문서/API_계약.md) 3절, 기획서 9.2, 5.1, 8절

두 규칙 모두 **기획서보다 이르게 잠그는** 결정입니다. 기획서가 열어 둔 것을 좁히는 방향이므로
근거가 남아야 합니다.

## 배경

기획서 9.2는 브리프 항목 대부분을 "수정 가능"으로 분류했고, 언제까지 수정 가능한지는 적지
않았습니다. 초안은 이것을 "확정(`finalized`) 전까지"로 읽었습니다.

그 해석에는 구멍이 있습니다. **시안은 브리프에서 생성된 산출물**인데, 시안이 나온 뒤에 브리프를
고칠 수 있으면 시안이 무엇에 근거했는지 알 수 없게 됩니다. 소구점을 고쳐도 이미 만들어진 카피는
옛 소구점에 근거한 채 남습니다. 그 상태로 확정하면 **입력에 없는 주장**이 결과물에 들어갑니다 --
INV-6이 막으려던 바로 그 상황이 검사 없이 통과합니다 (기획서 5.5).

광고 기획안(`adPlan`)에도 같은 성격의 문제가 있습니다. 기획서 8절은 이것을 시안과 함께 제시되는
산출물로 두었는데, 내용이 브리프와 겹칩니다. 양쪽을 따로 고칠 수 있으면 **브리프와 기획안이 서로
다른 말을 하는 시안**이 만들어집니다.

## 검토한 선택지

브리프 잠금 시점:

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. **`draft_generating` 진입 시** | 시안의 근거가 고정됨. 규칙이 하나 | 브리프를 고치려면 새 세션. 오타 하나에도 사진 재업로드까지 전부 다시 |
| B. `finalized` 시 (초안) | 사용자가 오래 고칠 수 있음 | 시안과 브리프가 어긋난 채 확정될 수 있음 |
| C. 고치면 시안을 자동 폐기 | 둘 다 만족 | 사용자가 만든 시안이 예고 없이 사라짐. 텍스트 생성 비용도 다시 |

광고 기획안:

| 선택지 | 장점 | 단점 |
|---|---|---|
| D. **읽기 전용 문자열** | 겹침 문제가 사라짐. patch 대상이 줄어 규약이 단순 | 문구만 다듬고 싶을 때 방법이 없음 |
| E. 구조화된 객체 + 수정 허용 | 세밀한 편집 | 브리프와 어긋날 수 있음. 필드 설계가 또 필요 |

## 결정

**A와 D를 택합니다.**

| 규칙 | 구현 | 위반 시 |
|---|---|---|
| INV-7 `draft_generating` 진입 이후 `brief` 변경 불가 | 상태 기계 전이 가드 | 409 `STATE_CONFLICT` |
| INV-8 `adPlan`은 patch 대상이 아님 | patch 처리기의 대상 필드 검사 | 422 `INVALID_REQUEST` |

C를 택하지 않은 이유는 **사용자가 잃는 것이 눈에 보이기 때문**입니다. 고쳤더니 시안이 사라지는
동작은, 막는 것보다 나쁩니다 -- 막으면 못 한 것이고 폐기하면 잃은 것입니다.

E를 택하지 않은 이유는 **겹침을 해소하지 못하기 때문**입니다. 필드를 나눠도 브리프와 같은 사실을
두 곳에 두는 구조는 그대로입니다.

## 결과

**생기는 제약**

- 브리프를 고치려면 **새 세션**입니다. 잠긴 뒤에 되돌리는 경로는 없습니다 (기획서 5.1).
- 따라서 `brief_ready`가 **되돌릴 수 없는 마지막 확인 지점**입니다. 화면이 그 사실을 알려야
  합니다. 알리지 않으면 사용자는 시안 생성 버튼이 무엇을 닫는지 모른 채 누릅니다.
- `adPlan`을 다듬고 싶으면 브리프를 고치고 시안을 다시 생성해야 하는데, 브리프가 잠겨 있으므로
  결국 새 세션입니다. **두 규칙이 겹쳐 새 세션 빈도가 올라갑니다.**

**어려워지는 것**

- 오타 하나에 세션을 새로 만들게 됩니다. 입력을 승계하는 수단이 없으면 사진 재업로드까지
  포함해 전부 다시입니다. 세션 파생 방식은 아직 미정입니다
  ([미결정_대장.md](../기술문서/미결정_대장.md) N15).

**쉬워지는 것**

- 시안이 어떤 브리프에서 나왔는지가 항상 확정됩니다. 지표를 측정할 때 입력과 출력의 짝이
  깨지지 않습니다.
- patch 규약이 단순해집니다. 교체 대상에서 빠지는 것이 명시적이라 서버가 먼저 거절합니다.

**재검토 신호**

- N15가 "세션 파생 지원"으로 결정될 때. 새 세션 비용이 낮아지므로 이 결정의 부담이 줄어듭니다.
- 사용자 시험에서 `brief_ready` 이탈률이 높게 나올 때. 잠금 경고가 과하게 무섭다는 신호입니다.
